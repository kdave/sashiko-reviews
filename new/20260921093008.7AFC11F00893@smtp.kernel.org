btrfs: make qgroup rescan work to handle fs freezing

This patch aims to prevent the qgroup rescan worker from failing PM suspension
by handling filesystem freezing gracefully. It makes rescan_should_stop()
return true if the fs is frozen and introduces btrfs_try_start_transaction()
to avoid sleeping on sb_start_intwrite().

Link: https://lore.kernel.org/linux-btrfs/mu8fq8a8.b9a9a1ae-dd6b-45a4-a415-5db853d61536@nod.at/

[Severity: Medium]
Will this unconditionally log a spurious error during an expected system
suspend?

If the primary rescan loop completes at least one leaf before being
interrupted by a freeze, did_leaf_rescans is true. The second transaction
start will also fail with -EINTR, which is then logged as a filesystem error
by btrfs_err(), even though the freeze interruption is expected.

[Severity: High]
Does this still allow the rescan worker to sleep indefinitely on a frozen
filesystem?

When btrfs_try_start_transaction() is called with BTRFS_RESERVE_FLUSH_ALL,
start_transaction() can perform blocking reservations before reaching the
non-blocking sb_start_intwrite_trylock() check. For example, if metadata
space is tight:

start_transaction()
  btrfs_delayed_refs_rsv_refill(fs_info, flush)

This can block waiting for background flushers to free space, but since the
filesystem is frozen, flushers will block unconditionally on
sb_start_intwrite(), keeping the freezable workqueue active and failing the
suspend.
