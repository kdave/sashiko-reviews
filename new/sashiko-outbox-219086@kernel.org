btrfs: avoid copying too much memory in the logical to ino ioctl

This commit reduces the copy_to_user() length in btrfs_ioctl_logical_to_ino()
to copy only the header and populated inode entries rather than the full
container size.

> --- a/fs/btrfs/ioctl.c

> @@ -3349,8 +3349,15 @@ static long btrfs_ioctl_logical_to_ino(struct btrfs_fs_info *fs_info,
>  	if (ret < 0)

> +	/*
> +	 * Copy only what we found instead of the whole data container. If for

> +	 * copy 16M instead of sizeof(*inodes) + 1 * (3 * sizeof(u64)).
> +	 * For each inode we find we add 3 elements to the inodes->val array:
> +	 * inode number, offset and root ID.

> +			   sizeof(*inodes) + inodes->elem_cnt * (3 * sizeof(u64)));

[Severity: High]
Can this read past the end of inodes and write past the user buffer at
loi->inodes?

build_ino_list() already increments inodes->elem_cnt by 3 for each inode
stored in inodes->val[]:

fs/btrfs/backref.c:build_ino_list() {
    ...
	if (inodes->bytes_left >= c) {
		inodes->bytes_left -= c;
		inodes->val[inodes->elem_cnt] = inum;
		inodes->val[inodes->elem_cnt + 1] = offset;
		inodes->val[inodes->elem_cnt + 2] = root;
		inodes->elem_cnt += 3;
	}
    ...
}

Multiplying inodes->elem_cnt by 3 * sizeof(u64) instead of sizeof(u64)
triples the payload byte count, so whenever the resolved inodes fill more
than one third of the container capacity, copy_to_user() reads past the
allocated inodes buffer and overwrites user memory past loi->size.

In addition, init_data_container() allows size < sizeof(*inodes) with
inodes->elem_cnt == 0, in which case copying sizeof(*inodes) bytes without
clamping to size writes past the user buffer.
