[Severity: High]
Does this bypass the retry fallback for fragmented conventional metadata block
groups, causing valid metadata allocations to fail prematurely with -ENOSPC?

When metadata allocation is requested, empty_size is passed to reserve
contiguous space for future COW operations. The per-block-group allocator
policy for conventional metadata block groups is correctly altered here to
BTRFS_EXTENT_ALLOC_CLUSTERED, forcing them to use the unclustered allocator.

The unclustered allocator strictly enforces the empty_size requirement.
If a conventional block group is fragmented, the search fails.

In standard non-zoned BTRFS, find_free_extent_update_loop() gracefully handles
this by transitioning to LOOP_NO_EMPTY_SIZE, clearing empty_size to 0, and
retrying the allocation.

However, because the global ffe_ctl->policy remains BTRFS_EXTENT_ALLOC_ZONED,
find_free_extent_update_loop() sees the original policy:

fs/btrfs/extent-tree.c:find_free_extent_update_loop() {
    ...
	if (ffe_ctl->loop == LOOP_NO_EMPTY_SIZE) {
		if (ffe_ctl->policy != BTRFS_EXTENT_ALLOC_CLUSTERED)
			return -ENOSPC;
    ...
}

This unconditionally aborts the search, skipping the empty_size retry
fallback that would allow the allocation to succeed with empty_size = 0.
