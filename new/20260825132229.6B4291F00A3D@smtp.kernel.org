[Severity: Medium]
Is there a race condition here between reading inode->prop_compress and
inode->prop_compress_level?

When creating a subvolume within a subdirectory, btrfs_create_new_inode()
fetches the parent subvolume root inode and passes it to
btrfs_inode_inherit_props() without acquiring its VFS i_rwsem.

Concurrently, if another thread modifies the compression property of the root
subvolume, this lockless read could see a mismatched compression combination
(e.g., combining a newly set algorithm with an old level, such as "lzo:15").

Since these fields are read independently without synchronization, could this
result in an invalid compression string being inherited and permanently stored
in the new subvolume's on-disk xattrs?
