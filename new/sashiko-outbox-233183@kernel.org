conventional stripes in zoned block groups, centralizes stripe activation

[Severity: Low]
Can a stripe with WP_MISSING_DEV be counted in both nr_active and
nr_missing when device->zone_info->max_active_zones is 0?

In btrfs_load_zone_info(), __set_bit(zone_idx, active) runs when
!device->zone_info->max_active_zones before querying the zone state, and
later failure paths (btrfs_get_dev_zone() returning -EIO or -EOPNOTSUPP, or
BLK_ZONE_COND_OFFLINE / BLK_ZONE_COND_READONLY) set info->alloc_offset to
WP_MISSING_DEV without clearing zone_idx in active:

fs/btrfs/zoned.c:btrfs_load_zone_info() {

    ...

	case BLK_ZONE_COND_READONLY:
		...
		info->alloc_offset = WP_MISSING_DEV;
		break;

Double-counting that stripe in nr_active + nr_missing can make
nr_active + nr_missing == map->num_stripes true while another present
sequential stripe is still inactive (marking the block group active without
calling btrfs_zone_activate()), or make nr_active + nr_missing exceed
map->num_stripes when all present stripes are already active.

[Severity: Medium]
Does btrfs_load_block_group_zone_info() misclassify a conventional block
group as mixed sequential/conventional when one of its stripes is
WP_MISSING_DEV?

Just above this hunk, any stripe whose alloc_offset is not WP_CONVENTIONAL
increments num_sequential:

fs/btrfs/zoned.c:btrfs_load_block_group_zone_info() {
    ...
		if (zone_info[i].alloc_offset == WP_CONVENTIONAL)
			num_conventional++;
		else
			num_sequential++;
	}

	if (num_sequential > 0)
		set_bit(BLOCK_GROUP_FLAG_SEQUENTIAL_ZONE, &cache->runtime_flags);
    ...
}

When a block group has only conventional present stripe(s) and a missing
stripe (WP_MISSING_DEV), num_sequential is incremented and
BLOCK_GROUP_FLAG_SEQUENTIAL_ZONE is set even though no sequential zone is
present.  The new mixed-zone logic then clears the active bit on the
conventional stripe(s) and calls btrfs_zone_activate(), placing the block
group on fs_info->zone_active_bgs without reserving any active zone.
Because BLOCK_GROUP_FLAG_SEQUENTIAL_ZONE is set, btrfs_zone_finish_one_bg()
can pick and finish this block group without freeing any active zone.
