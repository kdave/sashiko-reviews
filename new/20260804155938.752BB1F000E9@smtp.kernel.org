btrfs: pre-allocate delayed dir index for non-overwrite rename

For rename() without an overwrite target, pre-allocate the delayed
dir index before any btree modifications so that ENOMEM can be returned
before the source is unlinked from the old directory.

[Severity: High]
Does this leak the preallocated delayed dir index if btrfs_insert_dir_item()
fails during path allocation?

If btrfs_alloc_path() fails inside btrfs_insert_dir_item() and returns
-ENOMEM, the prealloc parameter is not freed by btrfs_insert_dir_item().
btrfs_add_link() propagates this -ENOMEM back here to btrfs_rename(). Since
prealloc.item is unconditionally set to NULL, the out_fail label will
skip the cleanup, leaking the btrfs_delayed_item allocation and reserved
metadata space.
