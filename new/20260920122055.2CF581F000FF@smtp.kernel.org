btrfs: test defrag --nocomp converts compressed extents to uncompressed

This commit adds a test to verify that the btrfs filesystem defragment
--nocomp command rewrites compressed extents as uncompressed ones. It checks
that the defrag ioctl takes precedence over the mount option and ensures that
maximum-sized compressed extents are processed.

[Severity: Medium]
Is there a missing -o flag for the mount options here?

Because _scratch_cycle_mount forwards its arguments to _scratch_mount,
passing just the string "compress=zlib" without -o causes a mount command
syntax error. This leaves the scratch device unmounted, causing the
subsequent checksum validation to read from an empty directory and
spuriously fail the test.
