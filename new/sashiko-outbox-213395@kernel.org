[Severity: High]
Does the reschedule path leak a reference on map?

btrfs_find_chunk_map_nolock() increments map->refs before returning the
chunk map, and because all btrfs_free_chunk_map() calls were removed,
that lookup reference is never dropped, preventing the struct
btrfs_chunk_map from being freed on chunk removal or unmount.  Calling
btrfs_free_chunk_map(map) right after btrfs_find_chunk_map_nolock()
while still holding mapping_tree_lock (as
btrfs_dev_replace_update_device_in_mapping_tree() does) would drop the
extra reference.
