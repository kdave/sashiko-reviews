[Severity: Medium]
Will this fail to wait for writeback if the filesystem is zoned?

Since btrfs_run_delalloc_range() skips the delayed compression for zoned
filesystems even when CONFIG_BTRFS_EXPERIMENTAL is enabled:

fs/btrfs/inode.c:btrfs_run_delalloc_range() {
    ...
    if (btrfs_inode_can_compress(inode) &&
        inode_need_compress(inode, start, end, false)) {
        if (IS_ENABLED(CONFIG_BTRFS_EXPERIMENTAL) && !zoned)
            return run_delalloc_delayed(inode, locked_folio, start, end);
        else if (run_delalloc_compressed(inode, locked_folio, start, end, wbc))
            return 1;
    }
    ...
}

If zoned is true, the write goes through run_delalloc_compressed() (the old
async path).

However, btrfs_defrag_file() only checks IS_ENABLED(CONFIG_BTRFS_EXPERIMENTAL).
If it calls filemap_write_and_wait_range() on a zoned filesystem, the wait
returns immediately because the old async path leaves the folio locked and
does not immediately set PAGECACHE_TAG_WRITEBACK.

This causes btrfs_defrag_file() to clear inode->defrag_compress too early.
Later, when the async worker compress_file_range() runs, it sees that
inode->defrag_compress is cleared and silently falls back to uncompressed
writes, ignoring the defragmentation compression request.

Does this check also need to account for whether the filesystem is zoned?
