[Severity: Critical]
Can this cause data loss under memory pressure? This kzalloc_obj() allocation
for delayed_bio_private occurs on the writeback path but lacks mempool backing.

If the allocation fails, the writeback path immediately fails the bio with
-ENOMEM. The error handling clears the folios' writeback state without
re-dirtying them, which causes the page cache to silently discard the dirty
data before it reaches disk.

The kernel block layer mandates that allocations required during the writeback
path must be mempool-backed to ensure forward progress and prevent memory
pressure from converting into data loss.
