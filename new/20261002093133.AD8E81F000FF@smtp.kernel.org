This commit adds a regression test to verify degraded RMW writes on
btrfs raid arrays when some blocks lack checksums. It sets up a 4-disk
pool, removes one disk, and executes a mixed-checksum workload on the
degraded mount.

[Severity: Medium]
Will this hardcoded 512M allocation fail with enospc on small scratch
devices?

The test executes fio with a hardcoded filesize of 512M without verifying
that the underlying scratch pool devices have sufficient capacity. In test
environments where the scratch device pool contains small partitions (e.g.
256MB each), a raid6 profile will provide roughly 512MB of raw capacity.
Metadata overhead will then cause the 512MB allocation to fail with an
out of space error, resulting in false positive test failures.

Should there be a require scratch size guard here?

[Severity: High]
Does this variable initialization result in an empty string?

SCRATCH_DEV_NAME is not an initialized bash array in standard fstests, as
the standard variable is SCRATCH_DEV_POOL. As a result, dev2 evaluates to
an empty string.

[Severity: High]
Are we silently failing to wipe the device because dev2 is empty?

Since dev2 is empty, wipefs is executed with an empty argument and silently
fails because stderr is redirected. This means no device is actually
destroyed, and the subsequent degraded mount is fully healthy. The degraded
RMW condition is never tested, which defeats the primary objective of the
test and yields a false positive pass.

Additionally, should we check the return values of these setup commands?

If the filesystem creation or wipefs commands fail, the devices are left
improperly formatted or intact, bypassing the degraded test condition.

> +	_scratch_mount -o degraded

[Severity: High]
Does missing error handling here lead to host filesystem pollution?

If the scratch mount fails (for example, due to a previous unmount failure),
the script proceeds and executes the 512MB workload directly into
the scratch mount directory. This will write to the host's root filesystem,
polluting the host environment and causing a false positive test pass.
