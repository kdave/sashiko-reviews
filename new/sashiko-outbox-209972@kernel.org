btrfs: fix block group ref leak when scrub races with unused bg deletion

This commit fixes a block group reference leak in btrfs_delete_unused_bgs()
by checking whether bg->bg_list is empty under fs_info->unused_bgs_lock
before taking a new reference and moving the block group to deleted_bgs.

[Severity: Critical]
This problem wasn't introduced by this patch, but can a similar race on
bg->bg_list corrupt fs_info->unused_bgs or trigger a duplicate zone reset
in btrfs_reset_unused_block_groups() [1]?

fs/btrfs/zoned.c:btrfs_reset_unused_block_groups() {
	...
		list_del_init(&bg->bg_list);
		spin_unlock(&fs_info->unused_bgs_lock);

		ret = zoned_reset_bg_in_place(bg, &reclaimed);
		if (ret || !reclaimed)
			goto requeue;

		btrfs_put_block_group(bg);
		...
requeue:
		list_add_tail(&bg->bg_list, &retry_list);
	...
}

While fs_info->unused_bgs_lock is dropped across zoned_reset_bg_in_place(),
neither bg->ro nor space_info->groups_sem is held, so a concurrent scrub can
re-add bg->bg_list to fs_info->unused_bgs:

CPU0                                CPU1
btrfs_reset_unused_block_groups()
  spin_lock(&unused_bgs_lock)
  list_del_init(&bg->bg_list)
  spin_unlock(&unused_bgs_lock)
  zoned_reset_bg_in_place(bg)
                                    scrub_enumerate_chunks()
                                      btrfs_dec_block_group_ro(bg)
                                        btrfs_mark_bg_unused(bg)
                                          spin_lock(&unused_bgs_lock)
                                          if (list_empty(&bg->bg_list))
                                            btrfs_get_block_group(bg)
                                            list_add_tail(&bg->bg_list,
                                                          &unused_bgs)
                                          spin_unlock(&unused_bgs_lock)
  requeue:
    list_add_tail(&bg->bg_list,
                  &retry_list)      <-- unlocked list corruption

If zoned_reset_bg_in_place() takes the requeue branch, list_add_tail()
overwrites bg->bg_list without holding fs_info->unused_bgs_lock, corrupting
fs_info->unused_bgs and leaking a reference.  If zoned_reset_bg_in_place()
succeeds instead, the reset block group is returned for new allocations
while still linked on fs_info->unused_bgs, so a later call to
btrfs_reset_unused_block_groups() can pop it again and issue a second
REQ_OP_ZONE_RESET on a reused zone.
