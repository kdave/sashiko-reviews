iomap: follow the alignment requirement for iomap_dio_hole_iter()

This commit introduces more strict alignment handling in iomap_dio_hole_iter()
to resolve a btrfs assertion failure with 8K block sizes on 4K page systems.
It extracts a new iomap_dio_alignment() helper to consistently compute
alignment for both IOMAP_HOLE and bio iterations.

[Severity: Critical]
Can iter->iomap.bdev be NULL when this is called for an unmapped extent?

If a filesystem (such as EROFS) returns IOMAP_HOLE from its iomap_begin()
callback, it may leave iomap->bdev uninitialized (NULL). If that filesystem
also doesn't set IOMAP_DIO_FSBLOCK_ALIGNED, bdev_logical_block_size() will
dereference the NULL pointer.
