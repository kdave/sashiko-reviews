btrfs: fix off by one super block end offset calculation in write_dev_supers()

This commit prevents skipping a superblock mirror write when its end offset
exactly matches the device's commit total bytes. It does this by changing
a >= comparison to > in write_dev_supers().

> diff --git a/fs/btrfs/disk-io.c b/fs/btrfs/disk-io.c
> index bfd7815a461ec..5730841ab56b6 100644
> --- a/fs/btrfs/disk-io.c
> +++ b/fs/btrfs/disk-io.c
> @@ -3887,8 +3887,7 @@ static int write_dev_supers(struct btrfs_device *device,
>  			atomic_inc(&device->sb_write_errors);
>  			continue;
>  		}
> -		if (bytenr + BTRFS_SUPER_INFO_SIZE >=
> -		    device->commit_total_bytes)
> +		if (bytenr + BTRFS_SUPER_INFO_SIZE > device->commit_total_bytes)
>  			break;

[Severity: High]
Since this changes the boundary condition to include superblocks that exactly
match the device size, does wait_dev_supers() need the same fix?

Looking at wait_dev_supers() in fs/btrfs/disk-io.c:

	for (i = 0; i < max_mirrors; i++) {
		...
		if (bytenr + BTRFS_SUPER_INFO_SIZE >=
		    device->commit_total_bytes)
			break;

		folio = filemap_get_folio(device->bdev->bd_mapping,
					  bytenr >> PAGE_SHIFT);
		...
		folio_wait_locked(folio);
		folio_put(folio);
	}

If the device size perfectly matches the end offset of a superblock mirror,
write_dev_supers() will now correctly issue the write. However, because
wait_dev_supers() still uses the >= operator, won't it break out early and
skip the folio_wait_locked() completion tracking?

Does skipping this wait break the filesystem write barrier guarantees,
allowing the transaction commit to complete before the write is confirmed
on disk?
