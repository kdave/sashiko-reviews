btrfs: enable experimental delayed compression support

This commit introduces experimental delayed compression for btrfs. It
allocates delayed extent maps and ordered extents at run_delalloc time,
delaying the actual compression and extent reservation until submission.

[Severity: High]
Does this error path clear unowned extent locks?

If an error occurs in run_delalloc_delayed() (for example, if
btrfs_is_shutdown() is true or btrfs_create_delayed_em() fails) before the
entire [start, end] range has been fully processed, the error path clears
EXTENT_LOCKED and EXTENT_DELALLOC for the entire remaining range [cur, end].

However, the loop only locks up to cur + cur_len - 1 (or nothing at all, if
cur == start).

Can this lead to a race condition where another thread's lock is silently
dropped, and does modifying EXTENT_DELALLOC without the lock violate Btrfs
state invariants?
