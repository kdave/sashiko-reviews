Subject: btrfs: use kvmalloc() for stripe buffer of scrub_stripe

This commit replaces the per-page array for a stripe buffer with a single
kvmalloc() allocation to cover the full stripe. This simplifies checksum
verification, RAID56 caching, and removes the need for complex cross-page

[Severity: Critical]
Is the page offset calculation correct here?

The offset_in_page() macro is being called with just 'offset' rather than
'stripe->buffer + offset'. If stripe->buffer was fulfilled by kmalloc() and
isn't perfectly page-aligned (for example, on architectures with 64K pages
or if SLUB debugging/KASAN adds redzones), this will drop the sub-page
offset of the base pointer.

When the block layer executes the bio, wouldn't this cause it to perform
DMA at the wrong offset within the page, leading to memory corruption or 
incorrect disk I/O?
