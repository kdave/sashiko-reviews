erofs: open via dedicated fs bdev helpers

This commit routes block device opens through dedicated filesystem bdev
helpers to ensure registration against the correct superblock. It also
introduces shutdown and dead-device states to fence I/O when backing
devices are removed.

[Severity: High]
Does the early return for flatdev configurations bypass this new shutdown
check?

Earlier in erofs_map_dev(), if the filesystem is mounted with devs->flatdev,
the function exits early:

        if (devs->flatdev) {
                map->m_pa += erofs_pos(sb, dif->uniaddr);
                up_read(&devs->rwsem);
                return 0;
        }

Since this returns directly, it skips the newly added erofs_is_shutdown(sb)
and dead device checks at the end of the function. Could this allow I/O to be
falsely submitted to a dead primary device during flatdev mappings?
