btrfs: dev-replace: fix missing barrier before waking bio counter waiters

btrfs_bio_counter_sub() gates the wakeup on cond_wake_up_nomb(), whose
bare waitqueue_active() requires a full barrier from the preceding code.
This commit uses cond_wake_up() instead to provide the necessary barrier.

[Severity: High]
This is a pre-existing issue, but does btrfs_bio_counter_inc_blocked() also
need a memory barrier?

Looking at btrfs_bio_counter_inc_blocked(), it increments the counter and
then checks BTRFS_FS_STATE_DEV_REPLACING:

	percpu_counter_inc(&fs_info->dev_replace.bio_counter);
	if (likely(!test_bit(BTRFS_FS_STATE_DEV_REPLACING,
			     &fs_info->fs_state)))

Without an smp_mb() after percpu_counter_inc(), could the condition check be
hoisted before the counter increment?

Similarly, in btrfs_rm_dev_replace_blocked(), there appears to be a missing
smp_mb__after_atomic() after setting the BTRFS_FS_STATE_DEV_REPLACING bit.

Could this allow the store to be delayed past the counter load, breaking
wait-free mutual exclusion between these two functions and leading to I/O
being issued to replaced or freed devices?
