[Severity: Medium]
Should BTRFS_ROOT_SCAN depend on BTRFS_FS=y && DEVTMPFS instead of
allowing BTRFS_FS=m and selecting DEVTMPFS?

BTRFS_FS is tristate, so default y enables BTRFS_ROOT_SCAN even when
btrfs is built as a module, where mounting a root filesystem without an
initrd is not possible and later patches in this series fail to link
btrfs.ko due to unexported symbols (root_wait, is_root_dev() and
block_class).  In addition, DEVTMPFS is a user-visible option in
drivers/base/Kconfig, so force-selecting it by default enables devtmpfs
and spawns kdevtmpfs whenever btrfs is enabled.
