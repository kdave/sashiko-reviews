generic: test replacing a xattr with a larger value

This commit introduces a new generic xfstests script to verify that replacing a
xattr's value with a larger one works correctly. It specifically exercises a
btrfs edge case where two xattrs share the same crc32c name hash and are
packed into the same btrfs item.

[Severity: Medium]
Is _fixed_by_fs_commit an intended helper? The standard xfstests helper is
_fixed_by_kernel_commit, and it doesn't take a subsystem name as the first
argument.

Also, because this is a generic test in tests/generic/, unconditionally
requiring a btrfs-specific commit will cause the test to be incorrectly
skipped on other filesystems like ext4 or XFS if the running kernel lacks
the btrfs commit. Does this check need to be conditionally applied only for
btrfs using an FSTYP guard?

if [ "$FSTYP" = "btrfs" ]; then
    _fixed_by_kernel_commit xxxxxxxxxxxx \
        "btrfs: fix xattr replace when multiple xattrs are packed..."
fi

> +_getfattr --absolute-names --dump $SCRATCH_MNT/testfile | _filter_scratch

[Severity: Medium]
Does the _exit command exist in the test framework or bash? _exit is neither
a standard bash builtin nor a recognized xfstests helper.

When execution reaches this termination point, bash will emit a command not
found error to stderr. This will cause the test to fail on every run because
the unexpected stderr output will not match the golden output file (806.out),
and the script will terminate with a non-zero exit status.

Should this use a standard termination pattern, like status=0; exit or
simply exit 0?
