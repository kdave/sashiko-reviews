xfs: introduce health state for corrupted fsverity metadata

This commit adds a new health state flag to track and report corrupted
fsverity metadata in XFS. It updates xfs_fsverity_get_descriptor() to mark
the inode sick when the fsverity descriptor size or position is invalid.

[Severity: Medium]
Since this patch introduces health reporting for corrupted fsverity metadata,
should we also call xfs_inode_mark_sick() for the earlier error paths in
xfs_fsverity_get_descriptor() when the descriptor blocks are completely
missing?

For example, when checking if the inode is empty or if the last block offset
is invalid:

	if (is_empty)
		return -ENODATA;

	last_block_offset =
		XFS_FSB_TO_B(mp, rec.br_startoff + rec.br_blockcount);
	if (last_block_offset <= xfs_fsverity_metadata_offset(ip))
		return -ENODATA;

If missing fsverity metadata on a verity-enabled inode is considered a
corruption, wouldn't returning -ENODATA without reporting it to the health
system delay detection and repair?
