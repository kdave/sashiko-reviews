btrfs: also validate compression levels in btrfs_compress_is_valid_type()

This commit changes btrfs_compress_is_valid_type() to use 
btrfs_match_compress_type() and btrfs_compress_str2level() for more robust
validation of compression strings. It also drops the len parameter, relying

[Severity: High]
Is it safe to assume this string is NUL-terminated?

The value buffer passed from the xattr subsystem into 
prop_compression_validate() is a raw buffer without guaranteed 
NUL-termination.

If strlen() is called on this buffer here, and it is subsequently processed
by btrfs_match_compress_type() or btrfs_compress_str2level() via 
kstrtoint(), could this result in out-of-bounds memory reads?
