fs: refuse to claim any frozen block device

setup_bdev_super() already refuses to bring a filesystem up on a frozen
block device but only for the primary device. Now that filesystems claim
every device through fs_bdev_file_open_by_{dev,path}(), do that check
once in the registration helper so it covers all of them.

[Severity: High]
Can a concurrent block device freeze and mount failure cause a deadlock here?

The nascent superblock is inserted into the hash table before checking if the
device is frozen. A concurrent fs_bdev_freeze() can find this superblock,
elevate its s_active reference count, and call fs_super_freeze().

fs_super_freeze() subsequently calls freeze_super(), which blocks waiting
for the superblock to become SB_BORN or SB_DYING:

fs/super.c:super_lock() {
    ...
    wait_var_event(&sb->s_flags, super_flags(sb, SB_BORN | SB_DYING));
}

Meanwhile, fs_bdev_register() detects the elevated freeze count and aborts
the mount. The mount failure path calls deactivate_locked_super(). Because
the freeze thread elevated s_active to 2, atomic_dec_and_test() drops it to
1 and returns false.

This causes deactivate_locked_super() to skip kill_sb(), meaning SB_DYING
is never set. Since the mount aborted, SB_BORN is also never set. Does
this leave the freeze thread blocked forever?

> +		fs_bdev_holder_put(h);

[Severity: High]
Does this error path handle concurrent RCU walkers correctly?

fs_bdev_holder_put() only unlinks the entry if fs_bdev_passive drops to 0.
If a concurrent RCU walker pinned the entry, passive drops to 1, leaving
the entry in the hash table with fs_bdev_active still set to 1.

If a retry occurs, fs_bdev_register() finds this zombie entry, increments
fs_bdev_active to 2, and returns 0, bypassing the freeze check. When the
RCU walker later drops its pin, the entry is freed, leaving the device
actively used but untracked.

[Severity: Low]
Is it intentional to remove the diagnostic warning here?

The patch moves the freeze check into fs_bdev_register(), which lacks access
to the fs_context. This removes the warnf() call. When a mount fails because
the device is frozen, users will only see a generic error without knowing
the actual cause.
