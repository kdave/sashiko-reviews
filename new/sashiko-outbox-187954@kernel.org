What happens when file_setattr() is called with FS_XFLAG_PTIME on a
filesystem that implements i_op->fileattr_set() without calling
fileattr_has_fsx()?

file_attr_to_fileattr() accepts FS_XFLAG_PTIME in fattr->fa_xflags and
passes it into fileattr_fill_xflags(), setting fa->fsx_valid = true and
fa->fsx_xflags |= FS_XFLAG_PTIME, without vfs_fileattr_set() or
fileattr_set_prepare() verifying whether the target filesystem supports
FS_XFLAG_PTIME (for example via old_ma.fsx_xflags & FS_XFLAG_PTIME).

When inode->i_op->fileattr_set() is invoked:

1. In XFS, xfs_fileattr_set() -> xfs_ioctl_setattr_xflags() translates
   only known XFS flags via xfs_flags2diflags() and xfs_flags2diflags2():

[Severity: High]
Does this check in fileattr_set_prepare() prevent privileged users from
clearing FS_IMMUTABLE_FL or FS_APPEND_FL on inodes on filesystems that
support ptime?

When a filesystem reports FS_XFLAG_PTIME in vfs_fileattr_get(dentry, &old_ma),
calling ioctl(fd, FS_IOC_SETFLAGS, &flags) (such as chattr -i or chattr -a)
runs ioctl_setflags() -> vfs_fileattr_set() with fa->flags_valid == true.
In vfs_fileattr_set(), the fa->flags_valid branch merges non-common xflags
from old_ma into fa:

    if (fa->flags_valid) {
        fa->fsx_xflags |= old_ma.fsx_xflags & ~FS_XFLAG_COMMON;
        ...
        fa->fsx_ptime = old_ma.fsx_ptime;
    }

The same state is reached if userspace does a read-modify-write via
file_getattr() and file_setattr() with FILE_ATTR_SIZE_VER1 to clear
FS_XFLAG_IMMUTABLE or FS_XFLAG_APPEND.

vfs_fileattr_set() then calls fileattr_set_prepare(inode, &old_ma, fa)
before inode->i_op->fileattr_set() updates inode->i_flags. Because
inode->i_flags still has S_IMMUTABLE or S_APPEND set, and fa->fsx_xflags
has FS_XFLAG_PTIME set, fileattr_set_prepare() hits:

    if (fa->fsx_xflags & FS_XFLAG_PTIME) {
        if (IS_IMMUTABLE(inode) || IS_APPEND(inode))
            return -EPERM;

and fails with -EPERM even when CAP_LINUX_IMMUTABLE is held and ptime is
not being modified (or while immutable/append is being cleared).
