[Severity: Low]
Can passing inode->prop_compress_level unconditionally by value to
btrfs_compress_typelevel2str() read an uninitialized field when
inode->prop_compress is BTRFS_COMPRESS_NONE?

In fs/btrfs/inode.c, btrfs_alloc_inode() allocates struct btrfs_inode from
btrfs_inode_cachep (whose init_once constructor only initializes
ei->vfs_inode) and sets ei->prop_compress without initializing
ei->prop_compress_level:

	ei->runtime_flags = 0;
	ei->prop_compress = BTRFS_COMPRESS_NONE;
	ei->defrag_compress = BTRFS_COMPRESS_NONE;

Similarly, in fs/btrfs/props.c, when the btrfs.compression property is set to
"no" or "none" (or reset with len == 0), prop_compression_apply() sets
inode->prop_compress to BTRFS_COMPRESS_NONE without initializing
inode->prop_compress_level:

	/* Set NOCOMPRESS flag */
	if ((len == 2 && strncmp("no", value, 2) == 0) ||
	    (len == 4 && strncmp("none", value, 4) == 0)) {
		inode->flags |= BTRFS_INODE_NOCOMPRESS;
		inode->flags &= ~BTRFS_INODE_COMPRESS;
		inode->prop_compress = BTRFS_COMPRESS_NONE;

		return 0;
	}

When a directory has btrfs.compression set to "no" or "none",
BTRFS_INODE_HAS_PROPS is set on the directory inode. Creating a child inode
in that directory calls btrfs_inode_inherit_props() ->
prop_compression_extract(), which now unconditionally loads the uninitialized
parent->prop_compress_level and passes it by value to
btrfs_compress_typelevel2str() (and the follow-up commit "btrfs: preserve
btrfs.compression when setting inode flags" similarly passes
inode->prop_compress_level from btrfs_fileattr_set() on inodes that never had
a compression property set).

While btrfs_compress_typelevel2str() switches on type first and ignores level
for BTRFS_COMPRESS_NONE in normal builds, won't passing an uninitialized
value as a function argument trigger a KMSAN uninit-value warning when
CONFIG_KMSAN_CHECK_PARAM_RETVAL=y is enabled?
