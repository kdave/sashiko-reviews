Will this cause mount failures on read-only devices?

The call chain from open_ctree() -> btrfs_restore_active_nondata_bgs() ->
finish_extra_active_nondata_bgs() calls do_zone_finish(), which ultimately
issues a blkdev_zone_mgmt(REQ_OP_ZONE_FINISH) write operation to the disk.

If the filesystem is mounted on a strictly read-only device (such as a
hardware write-protected drive during a data rescue scenario), won't this
attempt to write to the drive fail with an error like -EPERM, causing the
entire mount to abort?
