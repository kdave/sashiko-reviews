[Severity: Medium]
Can this break ioctl(FS_IOC_SETFLAGS) and corrupt ptime reads when an
inode has a pre-1970 creation time with sub-second precision?

When ntfs_read_mft() loads an inode from disk, it converts std5->cr_time
into ni->i_crtime via nt2kernel():

fs/ntfs3/ntfs_fs.h:nt2kernel() {
	s32 t32;
	/* use signed 64 bit to support timestamps prior to epoch. xfstest 258. */
	s64 t = le64_to_cpu(tm) - _100ns2seconds * SecondsToStartOf1970;

	ts->tv_sec = div_s64_rem(t, _100ns2seconds, &t32);
	ts->tv_nsec = t32 * 100;
}

For timestamps prior to 1970 with a non-zero sub-second remainder, t is
negative and div_s64_rem() produces a negative remainder t32, leaving
ni->i_crtime.tv_nsec negative instead of normalized.

Because ntfs_fileattr_get() now unconditionally sets FS_XFLAG_PTIME and
copies ni->i_crtime into fa->fsx_ptime, an unrelated ioctl(FS_IOC_SETFLAGS)
call on such an inode will populate old_ma via vfs_fileattr_get(), copy
old_ma.fsx_xflags and old_ma.fsx_ptime into fa in vfs_fileattr_set()
(since fa->fsx_valid is false), and then fail with -EINVAL in
fileattr_set_prepare():

fs/file_attr.c:fileattr_set_prepare() {
	...
	if (fa->fsx_xflags & FS_XFLAG_PTIME) {
		if ((unsigned long)fa->fsx_ptime.tv_nsec >= NSEC_PER_SEC)
			return -EINVAL;
	}
}

In addition, exposing a negative tv_nsec via fa->fsx_ptime in
ntfs_fileattr_get() and stat->ptime in ntfs_getattr() causes
fileattr_to_file_attr() and cp_statx() to wrap the negative value into
unsigned __u32 fa_ptime_nsec and stx_ptime.tv_nsec fields, with tv_sec
off by +1.

[Severity: Medium]
Does calling file_setattr() with FS_XFLAG_PTIME fail with -EOPNOTSUPP on
compressed or encrypted files, or on mounts using the nocase option?

When file_setattr() is called, file_attr_to_fileattr() calls
fileattr_fill_xflags(), which sets fa->fsx_valid = true and leaves
fa->flags_valid = false.

In vfs_fileattr_set(), vfs_fileattr_get(dentry, &old_ma) calls
ntfs_fileattr_get(), which populates old_ma.flags with FS_CASEFOLD_FL
(when sbi->options->nocase is set), FS_COMPR_FL (when is_compressed(ni)
is true), and FS_ENCRYPT_FL (when is_encrypted(ni) is true).

Because fa->flags_valid is false, vfs_fileattr_set() then merges the
existing non-common flags into fa->flags:

fs/file_attr.c:vfs_fileattr_set() {
	...
	if (!fa->flags_valid)
		fa->flags |= old_ma.flags & ~FS_COMMON_FL;
}

Since FS_CASEFOLD_FL, FS_COMPR_FL, and FS_ENCRYPT_FL are not part of
FS_COMMON_FL, they are copied into fa->flags, and the check in
ntfs_fileattr_set() rejects them with -EOPNOTSUPP.
