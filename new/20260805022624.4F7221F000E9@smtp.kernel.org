This patch ensures the extent and inode are unlocked if the pages array
allocation fails in btrfs_uring_read_extent(). It modifies the allocation
error paths to jump to out_fail instead of returning directly.

[Severity: High]
This is a pre-existing issue, but does this out_fail path cause a double-free
and double-unlock if btrfs_encoded_read_regular_fill_pages() fails
synchronously?

When btrfs_encoded_read_regular_fill_pages() experiences a synchronous error
(like an immediate BIO mapping failure), it queues task work and returns the
raw error (e.g., -EIO) instead of -EIOCBQUEUED:

fs/btrfs/inode.c:btrfs_encoded_read_regular_fill_pages() {
    ...
		if (refcount_dec_and_test(&priv->pending_refs)) {
			ret = blk_status_to_errno(READ_ONCE(priv->status));
			btrfs_uring_read_extent_endio(uring_ctx, ret);
			kfree(priv);
			return ret;
		}
    ...
}

In btrfs_uring_read_extent(), the caller sees a non-zero error that is not
-EIOCBQUEUED, assumes a synchronous failure, and jumps here to out_fail. This
prematurely frees priv (which was already freed above) and pages, and
double-unlocks the extent and inode.

Later, when the queued task work executes, it accesses the freed priv pointer
and double-frees pages.

> -			__free_page(pages[i]);

> +		for (int i = 0; i < nr_pages; i++) {
> +			if (pages[i])
> +				__free_page(pages[i]);
> +		}
>  	}
