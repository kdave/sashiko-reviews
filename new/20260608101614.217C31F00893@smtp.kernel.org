btrfs: do not overwrite NODATASUM flag when removing NODATACOW flag
    
This commit fixes an issue where setting the SYNC flag clears the NODATASUM
flag inherited from mount options. It does this by preventing the removal of
the NODATASUM flag when the NOCOW flag is absent.

[Severity: High]
When a user explicitly disables NOCOW via chattr -C on a zero-sized file,
does this change permanently and silently strip data checksumming?

Because BTRFS_INODE_NODATASUM is no longer cleared here, the file will appear
as a normal COW file (since the C attribute is no longer visible in lsattr),
but Btrfs might silently skip checksum generation for all future writes to
this file.

To fix the chattr +S bug without breaking chattr -C, would it be better to
check if FS_NOCOW_FL actually changed between old_fsflags and fsflags, and
only toggle NODATACOW and NODATASUM if a change to the NOCOW state was
explicitly requested?
