[Severity: High]
This is a pre-existing issue, but does this result in an out-of-bounds array
access when log_transid is 0?

When a user calls fsync() on a newly created btrfs subvolume for the
first time, btrfs_sync_log() is invoked with log_transid == 0. It then
calls wait_log_commit() with log_transid - 1, which passes -1 as transid:

btrfs_sync_log()
    wait_log_commit(root, log_transid - 1);

Inside wait_log_commit(), the modulo calculation evaluates to -1 in C:

    int index = transid % 2;

This causes a read from root->log_commit[-1]. On systems compiled with
UBSAN, this will trigger a warning and potentially a kernel panic if
panic_on_warn is enabled.
