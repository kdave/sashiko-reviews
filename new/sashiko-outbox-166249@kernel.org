[Severity: Low]
Does this patch belong in the xfstests-dev repository instead of the Linux
kernel tree?

The patch adds files to tests/btrfs/ and uses fstests specific infrastructure
such as _begin_fstest, _require_scratch_verity, and _filter_xfs_io. These
helpers and directory structures do not exist in the Linux kernel tree (which
uses tools/testing/selftests/). 

Applying this patch to the kernel tree simply introduces dead, unexecutable
files.

[Severity: Medium]
Does this undefined command cause an unconditional test failure?

_exit is not a valid bash builtin and is not defined in the standard fstests
common helpers. When execution reaches this line, bash will emit a command not
found error to stderr.

Because fstests captures standard error and compares it to the expected output
file (359.out), this unexpected error message will cause the test to
unconditionally fail regardless of the actual filesystem behavior.

Should this use status=0; exit or exit 0 instead?
