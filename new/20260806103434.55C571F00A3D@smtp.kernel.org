[Severity: Critical]
This is a pre-existing issue, but does taking the out_free error path cause
SLUB corruption if the iovcnt fits in UIO_FASTIOV?

Looking at btrfs_uring_encoded_read(), __import_iovec() is called and may
leave data->iov pointing to the embedded data->iovstack:

    data->iov = data->iovstack;
    ret = __import_iovec(..., ARRAY_SIZE(data->iovstack), &data->iov, ...);

Later in the out_free path:

    out_free:
        kfree(data->iov);
    
    out_acct:
        ...
        kfree(data);

If data->iov was not reallocated by __import_iovec(), it still points to
data->iovstack. Since data is a dynamically allocated kmalloc object,
data->iovstack is an interior pointer. 

Calling kfree(data->iov) on this interior pointer will corrupt the SLUB
freelist.
