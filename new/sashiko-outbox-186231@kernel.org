[Severity: Medium]
Should btrfs_zoned_dev_avail_bytes() also exclude the zones containing the
regular superblock offsets returned by btrfs_sb_offset(i)?

In btrfs_find_allocatable_zones() (and in exclude_super_stripes() in
fs/btrfs/block-group.c), the zoned chunk allocator unconditionally skips
any zone overlapping btrfs_sb_offset(i):

fs/btrfs/zoned.c:btrfs_find_allocatable_zones() {
	...
			/* We also need to exclude regular superblock positions */
			sb_pos = btrfs_sb_offset(i);
			if (!(pos + num_bytes <= sb_pos ||
			      sb_pos + BTRFS_SUPER_INFO_SIZE <= pos)) {
				have_sb = true;
				pos = ALIGN(sb_pos + BTRFS_SUPER_INFO_SIZE,
					    zinfo->zone_size);
				break;
			}
	...
}

Because sb_zone_number() places the log-structured superblock zone pairs at
0B, 512 GiB, and 4 TiB, whereas btrfs_sb_offset(i) places the regular
superblock offsets at 64 KiB, 64 MiB, and 256 GiB, the regular superblock
offsets fall into separate unallocatable zones in two cases:

1. For mirror 1 (64 MiB), when zinfo->zone_size is smaller than 64 MiB
   (4 MiB, 8 MiB, 16 MiB, or 32 MiB), the mirror 0 log zones [0,
   2 * zone_size) end at or before 64 MiB, so btrfs_sb_offset(1) lies in a
   distinct zone.

2. For mirror 2 (256 GiB), because BTRFS_MAX_ZONE_SIZE is 8 GiB, the zone
   containing 256 GiB never overlaps the log zones at 0B, 512 GiB, or
   4 TiB for any valid zone size on devices larger than 256 GiB.

Since chunks can never be allocated in those zones, they are never added to
device->bytes_used. Does omitting them here cause
btrfs_calc_avail_data_space() (and btrfs_zoned_data_chunk_allowed() in the
following patch "btrfs: zoned: keep a zone free for relocation when
allocating data chunks") to overcount available zones by 1 or 2 zones and
allow data chunk allocation to consume the last free zone reserved for
relocation?
