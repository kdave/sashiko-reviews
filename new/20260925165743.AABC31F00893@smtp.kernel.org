Is this intended to be _fixed_by_kernel_commit? 

The fixed_by_fs_commit function call is missing the standard '_' prefix used
for fstests helpers, which causes bash to emit a "command not found" error to
stderr. This stderr output will cause the test to fail unconditionally due to
a golden output mismatch.

Additionally, if the intent was to use _fixed_by_kernel_commit, it appears to
be incorrectly passing "btrfs" as its first argument instead of the commit
hash. Since this is a generic test, should this call be wrapped in a check for
$FSTYP == "btrfs" to prevent unrelated filesystems from incorrectly tracking
this btrfs-specific commit dependency?
