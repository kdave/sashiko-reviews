btrfs: use kvmalloc() for stripe buffer of scrub_stripe

This commit converts scrub_stripe to use a 64K kvmalloc() buffer instead of
an array of folios. This simplifies cross-page handling for checksum
verification, RAID56 caching, and bio assembly.

[Severity: Critical]
Is it safe to assume kvmalloc() returns page-aligned memory here? On
architectures where PAGE_SIZE is 64K (like ARM64 or PPC64), BTRFS_STRIPE_LEN
is exactly one page, so kvmalloc() uses the kmalloc-64k SLUB cache. If SLUB
debugging or KASAN is enabled, objects in this cache are not page-aligned
due to inserted redzones or metadata, which would cause this ASSERT to
trigger a kernel panic.
