[Severity: High]
This is a pre-existing issue, but should mapping_time be updated only if
filemap_invalidate_pages() succeeds?

If filemap_invalidate_pages() returns an error (such as -EBUSY due to
elevated refcounts from an active GUP pin), the error is returned to the
current caller but mapping_time is still updated to a future time.

Subsequent reads within the cache timeout window will then see
time_before(jiffies, orangefs_inode->mapping_time) as true and return
success without attempting to invalidate the page cache or fetch new data.

Could this result in stale data being served from the page cache?
