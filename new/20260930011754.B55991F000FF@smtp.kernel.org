btrfs: raid56: do not verify the content if there is no data checksum

This commit adds a check in verify_one_sector() to skip checksum verification
if there is no corresponding data checksum. This fixes an I/O error issue seen
during fsync on degraded RAID56 arrays.

Does this calculation incorrectly use addition instead of multiplication?

The previous code computed the index as
stripe_nr * rbio->stripe_nsectors + sector_nr.

Using addition here means the sector index can exceed the allocated bounds
of rbio->csum_bitmap and rbio->csum_buf. This arithmetic typo results in
incorrect sector indices being used, which could cause sectors to be verified
against the wrong checksums and lead to silent data corruption.
