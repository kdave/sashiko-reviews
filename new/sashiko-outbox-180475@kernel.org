Does checking for RAID stripe tree extents only in log_one_extent() miss
extents logged through copy_items()?

In btrfs_log_inode(), log_one_extent() is only reached via
btrfs_log_changed_extents() when fast_search is true. When
BTRFS_INODE_NEEDS_FULL_SYNC is set on the inode (for example, on every
newly created inode via btrfs_create_new_inode(), or after truncate, hole
punching, or reflink), fast_search remains false:

fs/btrfs/tree-log.c:btrfs_log_inode() {
	...
		if (test_bit(BTRFS_INODE_NEEDS_FULL_SYNC,
			     &inode->runtime_flags)) {
			if (log_mode == LOG_INODE_EXISTS) {
				max_key.type = BTRFS_XATTR_ITEM_KEY;
				if (ctx->logged_before)
					ret = drop_inode_items(trans, log, path,
							       inode, max_key.type);
			} else {
				clear_bit(BTRFS_INODE_NEEDS_FULL_SYNC,
					  &inode->runtime_flags);
				clear_bit(BTRFS_INODE_COPY_EVERYTHING,
					  &inode->runtime_flags);
				if (ctx->logged_before)
					ret = truncate_inode_items(trans, log,
								   inode, 0, 0);
			}
		}
	...
	ret = copy_inode_items_to_log(trans, inode, &min_key, &max_key,
				      path, dst_path, logged_isize,
				      log_mode, ctx, &need_log_inode_item);
	...
	if (fast_search) {
		ret = btrfs_log_changed_extents(trans, inode, dst_path, ctx);
		if (ret)
			goto out_unlock;
	} else if (log_mode == LOG_INODE_ALL) {
		struct extent_map *em, *n;

		write_lock(&em_tree->lock);
		list_for_each_entry_safe(em, n, &em_tree->modified_extents, list)
			list_del_init(&em->list);
		write_unlock(&em_tree->lock);
	}
}

In that full-sync path, btrfs_sync_file() waits for ordered extents to
complete into the uncommitted subvolume tree and uncommitted
fs_info->stripe_root, and then btrfs_log_inode() ->
copy_inode_items_to_log() -> copy_items() copies new
BTRFS_EXTENT_DATA_KEY items directly from the subvolume tree into the log
tree without checking if the extent requires a RAID stripe tree update.
Similarly, preallocated extents starting at or beyond i_size are skipped
in btrfs_log_changed_extents() and logged via
btrfs_log_prealloc_extents() -> copy_items().

When btrfs_log_dentry_safe() returns 0, btrfs_sync_file() only syncs the
log tree via btrfs_sync_log() and calls btrfs_end_transaction() without
committing the transaction:

fs/btrfs/file.c:btrfs_sync_file() {
	...
	if (!ret) {
		ret = btrfs_sync_log(trans, root, &ctx);
		if (!ret) {
			ret = btrfs_end_transaction(trans);
			goto out;
		}
	}
}
