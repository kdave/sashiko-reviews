[Severity: High]
This is a pre-existing issue, but does update_raid_extent_item() write 
item_size bytes into the existing btree item without verifying that the
existing item is large enough to hold the new data?

If a crafted filesystem contains a BTRFS_RAID_STRIPE_KEY item with a 
maliciously small size (e.g., 0 bytes), and btrfs_insert_item() returns 
-EEXIST, update_raid_extent_item() will locate the key and call:

    write_extent_buffer(leaf, stripe_extent, 
                        btrfs_item_ptr_offset(leaf, slot), item_size);

Since btrfs_item_size(leaf, slot) isn't checked against item_size, could
this blindly overwrite adjacent items' payload data in the B-tree leaf,
causing memory and metadata corruption?
