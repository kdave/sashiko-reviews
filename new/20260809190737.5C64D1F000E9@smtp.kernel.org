btrfs: support inheritance for per-inode compression levels

This commit modifies prop_compression_extract() to take an output buffer and
length, allowing it to dynamically append the compression level to the string.
This enables correctly inheriting both the compression algorithm and its level
for newly created files and directories.

[Severity: Medium]
Since btrfs_inode_inherit_props() reads from the parent inode locklessly,
could a concurrent setxattr cause a race here?

Evaluating inode->prop_compress in the switch statement and then fetching both
inode->prop_compress and inode->prop_compress_level again inside the snprintf
call might observe inconsistent states if modified concurrently.

This double-fetch could lead to generating a malformed property string or 
mixing a new algorithm with an old level, causing the inheritance to fail or 
apply an unintended state.
