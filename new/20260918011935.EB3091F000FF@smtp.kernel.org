btrfs: enable experimental delayed compression support

This commit enables experimental delayed compression support for btrfs.
It allocates delayed extent maps and ordered extents during run_delalloc
without reserving data extents, which are then assembled and intercepted
before submission to run compression and allocate real extents.

[Severity: High]
Does clearing EXTENT_DELALLOC here create a metadata reservation deficit?

In fs/btrfs/ordered-data.c, alloc_ordered_extent() explicitly skips
incrementing the outstanding_extents counter for delayed OEs. But
extent_clear_unlock_delalloc() unconditionally decrements
outstanding_extents when clearing EXTENT_DELALLOC.

It seems this would prematurely release the metadata reservation back to
space_info. When the compression worker later creates the real child OE, it
increments outstanding_extents but does not reserve space. Can this lead to
-ENOSPC transaction aborts?
