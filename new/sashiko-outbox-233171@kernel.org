[Severity: Medium]
As reported by Naohiro Aota on v2 [1], does excluding conventional-only
block groups from fs_info->zone_active_bgs prevent
prepare_allocation_zoned() from selecting them as allocation hints?

prepare_allocation_zoned() sets ffe_ctl->hint_byte for data allocations
solely by scanning fs_info->zone_active_bgs:

fs/btrfs/extent-tree.c:prepare_allocation_zoned() {
    ...
	spin_lock(&fs_info->zone_active_bgs_lock);
	list_for_each_entry(block_group, &fs_info->zone_active_bgs, active_bg_list) {
		u64 avail = block_group->zone_capacity - block_group->alloc_offset;

		if (block_group_bits(block_group, ffe_ctl->flags) &&
		    block_group->space_info == space_info &&
		    avail >= ffe_ctl->num_bytes) {
			ffe_ctl->hint_byte = block_group->start;
			break;
		}
	}
	spin_unlock(&fs_info->zone_active_bgs_lock);
    ...
}

When an active sequential data block group has enough free space,
prepare_allocation_zoned() will always point ffe_ctl->hint_byte to it and
skip open conventional data block groups until all active sequential data
block groups fill up.  When no sequential data block group satisfies the
request, ffe_ctl->hint_byte stays 0 and find_free_extent() falls back from
an rbtree lookup to a linear scan across space_info->block_groups[] on
every data extent allocation.
