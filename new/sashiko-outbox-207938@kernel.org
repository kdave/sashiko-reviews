[Severity: High]
This problem wasn't introduced by this patch, but can performing metadata
reservations with BTRFS_RESERVE_FLUSH_ALL in start_transaction() before
acquiring sb_start_intwrite() cause a freeze deadlock [1]?

btrfs_qgroup_rescan_worker() calls btrfs_start_transaction() with
num_items == 0, which runs btrfs_delayed_refs_rsv_refill() (or
btrfs_reserve_trans_metadata() when num_items > 0) with
BTRFS_RESERVE_FLUSH_ALL before reaching the sb_start_intwrite() check:

fs/btrfs/transaction.c:start_transaction() {
	...
	} else if (num_items == 0 && flush == BTRFS_RESERVE_FLUSH_ALL &&
		   !btrfs_block_rsv_full(delayed_refs_rsv)) {
		ret = btrfs_delayed_refs_rsv_refill(fs_info, flush);
		...
	}
again:
	...
	if (type & TRANS_SB_INTWRITER_MASK)
		sb_start_intwrite(fs_info->sb);
}

When metadata space is tight while the filesystem is being frozen (for
example during system suspend), the flush path can call
btrfs_join_transaction() and block in sb_start_intwrite(), deadlocking
against the freeze operation waiting for the btrfs workqueues to drain.
