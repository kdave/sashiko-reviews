btrfs: convert struct btrfs_io_ctl to use folios

This commit updates struct btrfs_io_ctl to use folios rather than pages.
It replaces page APIs with folio APIs for memory mapping and management
operations, removing old page-based calls.

[Severity: Critical]
This isn't a bug introduced by this patch, but does this bounds check leave
the read path vulnerable to a malicious filesystem image?

If write is 0 during mounting or loading, the bounds check for the number
of folios is entirely bypassed. A maliciously crafted free space cache inode
could provide an arbitrarily large i_size, resulting in a massive num_folios
value that will be propagated into the read path.

[Severity: Critical]
This is also a pre-existing issue, but can this offset calculation cause
an integer underflow in the crc check?

If the free space cache inode was maliciously sized and bypassed the bounds
check in io_ctl_init(), offset will exceed PAGE_SIZE here.

Later in io_ctl_check_crc(), this unchecked offset is used in a subtraction
for the length parameter:

    crc = crc32c(crc, io_ctl->orig + offset, PAGE_SIZE - offset);

Because offset is larger than PAGE_SIZE, PAGE_SIZE - offset underflows into
a massive unsigned size_t. This would cause crc32c() to read out of bounds
until a page fault panics the system.
