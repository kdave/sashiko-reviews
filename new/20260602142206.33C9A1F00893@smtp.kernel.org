[Severity: High]
Will this assertion cause a NULL pointer dereference on the success path?

The ASSERT macro in fs/btrfs/messages.h evaluates its formatting arguments
unconditionally by passing them to verify_assert_printk_format() before
checking the condition.

When node->eb is indeed NULL (the normal, successful path), the macro still
evaluates the argument node->eb->start. Can this dereference the NULL pointer
and cause a crash?
