[Severity: High]
This is a pre-existing issue, but does failing validation here during a 
remount leak the BTRFS_FS_STATE_REMOUNTING bit?

Because this patch makes usebackuproot a forced RO option, an administrator 
mistakenly trying to remount rw a filesystem initially mounted 
with rescue=usebackuproot will have btrfs_check_options() reject the 
remount. 

Looking at btrfs_reconfigure(), it appears this validation failure directly 
returns without clearing the remounting bit:

fs/btrfs/super.c:btrfs_reconfigure() {
    ...
    set_bit(BTRFS_FS_STATE_REMOUNTING, &fs_info->fs_state);

    if (!btrfs_check_options(fs_info, &ctx->mount_opt, fc->sb_flags))
        return -EINVAL;
    ...
}

Does this permanently disable auto-defrag, background space reclaim, and 
qgroup rescanning until the filesystem is completely unmounted?
