[Severity: High]
This is a pre-existing issue, but propagating this error exposes a flaw where
a failure in do_zone_finish() skips critical cleanup.

Looking at do_zone_finish() in fs/btrfs/zoned.c, if call_zone_finish() fails,
it returns early:

fs/btrfs/zoned.c:do_zone_finish() {
    ...
    for (i = 0; i < map->num_stripes; i++) {
        ret = call_zone_finish(block_group, &map->stripes[i]);
        if (ret) {
            up_read(&dev_replace->rwsem);
            return ret;
        }
    }
    ...
}

Could this early return cause deadlocks and memory leaks by bypassing the
list removal and bit-clearing steps below?

fs/btrfs/zoned.c:do_zone_finish() {
    ...
    spin_lock(&fs_info->zone_active_bgs_lock);
    ASSERT(!list_empty(&block_group->active_bg_list));
    list_del_init(&block_group->active_bg_list);
    spin_unlock(&fs_info->zone_active_bgs_lock);

    /* For active_bg_list */
    btrfs_put_block_group(block_group);

    clear_and_wake_up_bit(BTRFS_FS_NEED_ZONE_FINISH, &fs_info->flags);
    ...
}

Without this cleanup, the block group leaks its reference and stays
indefinitely on active_bg_list, which would leave other threads waiting
permanently on BTRFS_FS_NEED_ZONE_FINISH.

Furthermore, does this leftover state lead to an infinite loop in
btrfs_zoned_activate_one_bg()?

If the block group remains on zone_active_bgs but its ZONE_IS_ACTIVE bit
is cleared (which happens before call_zone_finish), btrfs_zone_finish_one_bg()
might continuously select it as the min_bg.

Since do_zone_finish() immediately returns 0 when the active bit is unset,
btrfs_zone_finish_one_bg() would return 1 (success/retry), causing the
for (;;) loop in btrfs_zoned_activate_one_bg() to retry endlessly.
