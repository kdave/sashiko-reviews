btrfs: export btrfs_match_compress_type(), move it to compression.h

This commit exports btrfs_match_compress_type() from a static function
in super.c to compression.c and exposes it in compression.h. This allows
it to be used in other files as validation for compression algorithm names.

[Severity: Low]
Is this documentation accurate regarding the may_have_level parameter?

The comment states the function returns true if the string matches the
type and, if may_have_level is true, has a level suffix. This implies a level
suffix is mandatory when may_have_level is true.

However, looking at the code below, the function also returns true for
exact matches without a suffix (string[len] == '\0') regardless of the
may_have_level flag.

Could the kernel-doc be updated to clarify that the suffix is optional even
when may_have_level is true?

> +bool btrfs_match_compress_type(const char *string, const char *type, bool may_have_level)
> +{
> +	const int len = strlen(type);
> +
> +	return (strncmp(string, type, len) == 0) &&
