btrfs: zoned: finish active block group cleanup if call_zone_finish() fails

do_zone_finish() previously returned early on a call_zone_finish() failure,
leaving the block group active and causing an infinite retry loop. This
commit changes the code to break the loop on failure and proceed with the
block group cleanup instead.

[Severity: High]
This is a pre-existing issue, but does breaking out of this loop early
permanently leak active zones on the remaining healthy devices?

In a multi-stripe zoned profile (like DUP or RAID1), if call_zone_finish()
fails for one stripe due to an IO error or device loss, the break statement
aborts the loop in do_zone_finish() and skips finishing the remaining stripes.

Previously, returning early caused an infinite retry loop. Since this patch
now falls through to the cleanup phase and removes the block group from the
active list, does this mean the remaining healthy stripes are never retried?

If so, this would permanently leak their hardware active zones and Btrfs
in-memory active zone accounting. Zoned devices typically have strict active
zone limits which could quickly be exhausted if leaked, eventually preventing
new allocations and failing the filesystem.
