fstests: btrfs: add a new test case for fstrim crash

This patch introduces a new test case to verify that fstrim does not crash
when a missing device reappears. It creates a RAID1 filesystem, mounts it in
degraded mode, allows the missing device to reappear, and then runs fstrim.

Link: https://lore.kernel.org/linux-btrfs/wlwir19t.fsf@damenly.org/

[Severity: High]
Does _require_batched_discard check the correct filesystem here? Because it is
called before _mount, the SCRATCH_MNT directory is still unmounted, meaning
this will evaluate the discard capability of the underlying host filesystem
rather than the btrfs scratch filesystem.

[Severity: High]
What happens if the _mount command fails? If the mount operation fails and the
script continues, SCRATCH_MNT will still point to the underlying host
filesystem.
