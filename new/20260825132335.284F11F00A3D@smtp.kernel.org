[Severity: Medium]
Does this read uninitialized memory and trigger a KMSAN
use-of-uninitialized-value warning?

Looking at btrfs_alloc_inode() in fs/btrfs/inode.c, a newly allocated inode
does not initialize prop_compress_level:

fs/btrfs/inode.c:btrfs_alloc_inode() {
        ...
        ei->prop_compress = BTRFS_COMPRESS_NONE;
        ei->defrag_compress = BTRFS_COMPRESS_NONE;
        /* prop_compress_level is left uninitialized */
        ...
}

If a user calls FS_IOC_SETFLAGS on a newly created file, this newly added
fallback logic reads the uninitialized inode->prop_compress_level and
passes it by value.

Even though the uninitialized value is logically ignored by the callee when
type == BTRFS_COMPRESS_NONE, passing uninitialized memory by value is
undefined behavior and can panic kernels where panic_on_warn is enabled for
KMSAN.
