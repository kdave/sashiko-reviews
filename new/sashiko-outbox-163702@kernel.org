[Severity: High]
Does this conditional removal allow a deleted root to remain on the dirty list
if there are concurrent references?

If a concurrent ioctl or subsystem holds a reference to the root when
btrfs_quota_disable() drops its reference, the refcount will remain > 0
and the root will not be unlinked from dirty_cowonly_roots.

Later, when commit_cowonly_roots() processes the deleted root, it calls
update_cowonly_root():

fs/btrfs/transaction.c:commit_cowonly_roots() {
    ...
    ret = update_cowonly_root(trans, root);
    if (ret)
        return ret;
    ...
}

Because the root item was already destroyed by btrfs_del_root(), does this
cause the update to fail with -EUCLEAN and abort the transaction?
