Will this ALLOW_ERROR_INJECTION bypass the corruption reporting mechanisms?

When fail_function triggers here, it intercepts execution at the entry of
btrfs_data_csum_ok() and immediately returns false. This completely skips the
internal zeroit block where the corruption reporting happens:

zeroit:
	btrfs_print_data_csum_error(inode, file_offset, csum, csum_expected,
				    bbio->mirror_num);
	if (dev)
		btrfs_dev_stat_inc_and_print(dev, BTRFS_DEV_STAT_CORRUPTION_ERRS);
	for (int i = 0; i < nr_steps; i++)
		memzero_page(phys_to_page(paddrs[i]), offset_in_page(paddrs[i]), step);
	return false;

Since higher-level callers like repair_one_sector() only log read errors
and do not increment the corruption stat, doesn't this break the commit's
stated goal of validating the full error detection and reporting path?
The primary reporting mechanisms (the printk and the stat increment)
appear to be skipped.
