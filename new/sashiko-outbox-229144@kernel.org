[Severity: Critical]
This problem wasn't introduced by this patch, but right below this hunk
should btrfs_init_dev_replace_tgtdev() use list_add_rcu() instead of
list_add() when linking device->dev_list into fs_devices->devices [1]?

fs/btrfs/dev-replace.c:btrfs_init_dev_replace_tgtdev() {
	...
	mutex_lock(&fs_devices->device_list_mutex);
	list_add(&device->dev_list, &fs_devices->devices);
	fs_devices->num_devices++;
	...
}

Without list_add_rcu(), the list pointer updates can become visible before
the initialization of struct btrfs_device completes, allowing concurrent RCU
readers walking fs_devices->devices via list_for_each_entry_rcu() to observe
uninitialized fields and trigger a NULL pointer dereference.
