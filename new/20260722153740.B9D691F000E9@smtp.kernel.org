btrfs: move condition for log commit wait into wait_log_commit()

This commit moves the check for a non-zero log_commit flag into the
wait_log_commit() function itself, allowing callers to invoke it
unconditionally.

[Severity: High]
Does this code perform an out-of-bounds array access when transid is -1?

In C, -1 % 2 evaluates to -1, which causes index to be -1.
This leads to accessing root->log_commit[-1] here and later
root->log_commit_wait[-1], which causes undefined behavior and can alias
other struct members like log_writers and log_writer_wait.

[Severity: High]
Is it possible for log_transid to be 0 here during the first log transaction?

If so, this will unconditionally pass -1 to wait_log_commit().
Before this patch, the code computed (index1 + 1) % 2 which correctly mapped
0 to 1, and conditionally skipped the function call entirely, avoiding the
negative modulo issue.
