btrfs: handle zero num_stripes in btrfs_chunk_item_size()

This commit removes ASSERT(num_stripes) from btrfs_chunk_item_size() and
computes the chunk item size from offsetof(struct btrfs_chunk, stripe) so
that zero-stripe system chunks in validate_sys_chunk_array() reach
btrfs_check_chunk_valid() instead of triggering an assertion failure.

Link: https://lore.kernel.org/linux-btrfs/d2ee0cc1-674e-4447-88da-d346122a43a4@suse.com/

Does btrfs_check_chunk_valid() reject a zero-stripe system chunk if
BTRFS_BLOCK_GROUP_REMAPPED is also set?

In validate_sys_chunk_array(), after btrfs_chunk_item_size(0) returns 48,
validation relies on btrfs_check_chunk_valid():

			goto short_read;

		if (unlikely(!(type & BTRFS_BLOCK_GROUP_SYSTEM))) {
			...
			return -EUCLEAN;

}

However, in btrfs_check_chunk_valid(), the zero-stripe checks are skipped
when BTRFS_BLOCK_GROUP_REMAPPED is set (with
BTRFS_FEATURE_INCOMPAT_REMAP_TREE enabled in the superblock), and neither
validate_sys_chunk_array() nor btrfs_check_chunk_valid() forbids
BTRFS_BLOCK_GROUP_REMAPPED on BTRFS_BLOCK_GROUP_SYSTEM (or
BTRFS_BLOCK_GROUP_METADATA_REMAP) chunks:

fs/btrfs/tree-checker.c:btrfs_check_chunk_valid() {
	...
	remapped = (type & BTRFS_BLOCK_GROUP_REMAPPED);

	if (unlikely(!remapped && !num_stripes)) {
		chunk_err(fs_info, leaf, chunk, logical,
			  "invalid chunk num_stripes, have %u", num_stripes);
		return -EUCLEAN;
	}
	...
}

If a crafted image has a 0-stripe system chunk with
BTRFS_BLOCK_GROUP_SYSTEM | BTRFS_BLOCK_GROUP_REMAPPED in
sb->sys_chunk_array, validate_sys_chunk_array() and btrfs_read_sys_array()
accept it. When open_ctree() then calls load_super_root(chunk_root, ...)
before init_tree_roots() -> load_important_roots() has loaded
fs_info->remap_root->node, btrfs_map_block() calls
btrfs_translate_remap() -> btrfs_search_slot() ->
btrfs_read_lock_root_node() -> btrfs_root_node(), dereferencing a NULL
root->node. Even after remap_root is loaded, a 0-stripe remapped chunk
hitting a BTRFS_IDENTITY_REMAP_KEY entry in btrfs_translate_remap() will
proceed in btrfs_map_block() to map_blocks_single() or map_blocks_raid0()
and divide by map->num_stripes (0).

Should btrfs_check_chunk_valid() reject BTRFS_BLOCK_GROUP_REMAPPED on
BTRFS_BLOCK_GROUP_SYSTEM and BTRFS_BLOCK_GROUP_METADATA_REMAP chunks, or
should validate_sys_chunk_array() also reject !num_stripes?
