btrfs: zoned: protect sb_write_pointer() reads with invalidate lock

This commit adds filemap_invalidate_lock() and unlock() around the
read_cache_page_gfp() calls in sb_write_pointer(). This ensures that the
zoned superblock discovery reads share the same synchronization domain as
the final read in btrfs_read_disk_super(), avoiding races with concurrent
mapping updates.

[Severity: High]
This is a pre-existing issue, but does this assignment miss the page offset
for architectures where the page size is greater than 4KB?

In Btrfs zoned mode, the superblock log is located at
zone_end - BTRFS_SUPER_INFO_SIZE (which is 4096 bytes). On architectures
with a page size larger than 4KB, such as 64KB on ARM64 or PPC64, bytenr
will not be page-aligned.

Since read_cache_page_gfp() retrieves the entire page, page_address() points
to the beginning of the page. Without adding offset_in_page(bytenr), does
this read arbitrary memory instead of the valid 4KB superblock?

The same missing offset_in_page() logic appears to be present in
btrfs_read_disk_super() when it maps the read page cache:

fs/btrfs/volumes.c:btrfs_read_disk_super() {
    ...
    page = read_mapping_page(mapping, bytenr >> PAGE_SHIFT, NULL);
    ...
    super = page_address(page);
    ...
}
