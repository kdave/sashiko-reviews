[Severity: High]
This is a pre-existing issue, but is there a missing bounds validation for
namelen against semantic filesystem limits?

While the check_inode_extref() function ensures the item does not overflow
the extent buffer boundary, it seems to omit checking namelen against limits
like BTRFS_NAME_LEN or ensuring it is non-zero, which is typically done in
the sibling check_inode_ref() function.

Could this allow malformed inode_extref items with 0-length names or
oversized names to bypass the btree checker?

Processing these invalid names downstream during log replay or backref
resolution might lead to logic errors, zero-size pointer allocations, or
transaction aborts that can cause mount failures.
