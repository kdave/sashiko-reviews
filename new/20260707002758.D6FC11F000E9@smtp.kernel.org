fstests: generic: add a basic cachestat test case

This commit introduces a new generic fstests case to verify the behavior of
cachestat. It performs buffered writes of various page sizes, checks that the
cached and dirtied page counts match, and then verifies the dirty count drops
to zero after an fsync.

[Severity: Medium]
Should this test explicitly exclude dax and sync mount options? 

If run with MOUNT_OPTIONS="-o sync", writes are flushed immediately and the
dirty page count will be 0. With "-o dax", writes bypass the page cache
entirely, causing cached pages to be 0. Both of these will cause the strict
equality checks in this test to spuriously fail.

[Severity: Medium]
Does separating the pwrite and cachestat commands into two different xfs_io
invocations create a race window against background writeback? 

It looks like the kernel background writeback threads could wake up between
the two process executions and flush the pages to disk. This would cause the
dirty page count to drop below the expected number and lead to intermittent
test failures on slower or heavily loaded systems. 

Could both commands be run together in a single xfs_io invocation?
