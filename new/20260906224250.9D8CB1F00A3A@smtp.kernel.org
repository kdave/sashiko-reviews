[Severity: High]
This is a pre-existing issue, but could this integer math underflow and read
massive amounts of unmapped memory?

In io_ctl_init(), the bounds check on num_folios is skipped on the read path
when write == 0:

    if (write && (num_folios * sizeof(u32) + sizeof(u64)) > PAGE_SIZE)
        return -ENOSPC;

If a maliciously crafted image provides a very large i_size, num_folios can be
huge. When io_ctl_check_crc() is called for index == 0, offset is calculated
as sizeof(u32) * io_ctl->num_folios. 

If this offset is greater than PAGE_SIZE, the PAGE_SIZE - offset calculation
will underflow into a massive size_t value passed to crc32c(). Could this 
cause an out-of-bounds read and an immediate kernel panic?
