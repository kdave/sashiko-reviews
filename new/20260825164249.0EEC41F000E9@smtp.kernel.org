btrfs: handle ENOMEM from btrfs_insert_dir_item() without aborting

The commit modifies btrfs_create_new_inode() and btrfs_add_link() to gracefully
handle -ENOMEM from btrfs_insert_dir_item() without aborting the transaction.
It adds the newly created inode to the orphan list and jumps to the discard
label when an out-of-memory error occurs.

[Severity: Medium]
Will this error path permanently leak the new inode, INODE_REF, and orphan item
in the btree on the active filesystem?

The error path adds the inode to the orphan list and jumps to discard without
aborting the transaction, leaving the items in the committed btree.

When discard_new_inode() runs, it marks the inode as bad. This causes
btrfs_evict_inode() to unconditionally skip on-disk cleanup:

fs/btrfs/inode.c:btrfs_evict_inode() {
...
	if (is_bad_inode(inode))
		goto out;
...
}

Because Btrfs only runs orphan cleanup at mount time, won't these metadata
items accumulate and permanently consume space on the live filesystem until it
is remounted?
