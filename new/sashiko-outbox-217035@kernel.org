delayed_root->items elevated after btrfs_release_delayed_inode() clears

[Severity: Low]
Should if (trans) be left without unlikely() here, as done in
walk_down_log_tree() and free_log_tree() in this patch?

The outer if (unlikely(ret)) already marks the error path as unlikely, and
inside it trans is non-NULL for every error after btrfs_join_transaction().

[Severity: High]
This problem wasn't introduced by this patch, but does
move_existing_remap() jump to end with path still write-locked [2]
when copy_remapped_data() fails?

fs/btrfs/relocation.c:move_existing_remap() {
    ...
	ret = btrfs_search_slot(trans, fs_info->remap_root, &key, path, 0, 1);
	if (ret == 1) {
		btrfs_release_path(path);
		ret = 0;
		goto end;
	} else if (unlikely(ret)) {
		goto end;
	}

	ret = copy_remapped_data(fs_info, new_addr, dest_addr, dest_length);
	if (unlikely(ret))
		goto end;
    ...
}

When btrfs_search_slot() returns 0, path holds a write lock on the leaf in
fs_info->remap_root.  If copy_remapped_data() fails, jumping to end without
calling btrfs_release_path(path) leaves the leaf write-locked across
btrfs_free_reserved_extent() and btrfs_end_transaction().
