btrfs: don't pass tree_id in btrfs_search_path_in_tree()

The 'tree_id' parameter in btrfs_search_path_in_tree() was only being
used in order to fetch the root tree to be considered for the search.
This commit replaces it with a single 'struct btrfs_root' parameter,
letting the caller handle the root allocation.

[Severity: Critical]
If args->treeid is non-zero, new_root is set to true here. If an
unprivileged user calls this ioctl, the subsequent capable(CAP_SYS_ADMIN)
check fails and jumps to the out label:

fs/btrfs/ioctl.c:btrfs_ioctl_ino_lookup() {

    if (!capable(CAP_SYS_ADMIN)) {
        ret = -EPERM;
        goto out;

}

Since the jump to out happens before btrfs_get_fs_root() is called, does
the cleanup code at the out label end up dropping a reference on the
original, caller-provided root? This appears to cause a refcount underflow
on the original btrfs_root structure.
