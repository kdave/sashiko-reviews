btrfs: restore active device pointers after failed sprout
    
This commit restores the active device pointers to the latest seed device
before removing and releasing a failed sprout device. This prevents a
crash when btrfs_show_devname() subsequently dereferences a freed
latest_dev pointer.

[Severity: High]
This is a pre-existing issue, but while this patch restores the active
device pointer to prevent one crash, does it leave the device exposed to a
use-after-free via RCU?

Further down in this same error path, the device is removed from the RCU
list and immediately freed:

btrfs_init_new_device() {
    ...
error_sysfs:
    ...
    list_del_rcu(&device->dev_list);
    ...
error_free_device:
    btrfs_free_device(device);
    ...
}

Because btrfs_free_device() directly frees the memory via kfree() without
waiting for an RCU grace period (e.g., using synchronize_rcu() or
kfree_rcu()), concurrent RCU readers iterating fs_devices->devices could
dereference the freed device.

Additionally, any RCU reader that read the old latest_dev pointer before
this restoration could still access the freed memory during the grace
period. Should this error path ensure an RCU grace period elapses before
freeing the device?
