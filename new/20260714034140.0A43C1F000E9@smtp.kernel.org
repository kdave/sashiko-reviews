btrfs: zoned: fix missing chunk metadata reservation

This commit fixes a bug where a successful return from
btrfs_zoned_activate_one_bg() would overwrite the return value,
inadvertently skipping chunk tree metadata reservation. It introduces a
separate variable for the activation result so success does not affect
the reservation.

Fixes: b6a98021e401 ("btrfs: zoned: activate necessary block group")

[Severity: High]
This isn't a bug introduced by this patch, but is it safe to return early
here if btrfs_zoned_activate_one_bg() fails?

The newly created block group was already added to trans->new_bgs by the
earlier call to btrfs_create_chunk(). By returning early, we skip the metadata
space reservation and btrfs_chunk_alloc_add_chunk_item().

Later in the transaction, btrfs_create_pending_block_groups() processes this
block group and attempts to insert its items into the chunk tree without the
required metadata reservation:

fs/btrfs/block-group.c:btrfs_create_pending_block_groups() {
    ...
    ret = btrfs_chunk_alloc_add_chunk_item(trans, block_group);
    mutex_unlock(&fs_info->chunk_mutex);
    if (ret)
        btrfs_abort_transaction(trans, ret);
    ...
}

Could this lead to an -ENOSPC error and trigger a transaction abort, since
the space was never reserved?
