btrfs: zoned: reset active_meta_bg on zone finish

block group from zone_active_bgs, but only the pivot path in
check_bg_is_active() resets fs_info->active_meta_bg / active_system_bg.

do_zone_finish() so it can never go stale.

[Severity: Critical]
Is it possible for *tgt to be NULL here?

Since do_zone_finish() now sets *active_bg = NULL, if
btrfs_check_meta_write_pointer() is called when fs_info->active_meta_bg
is NULL, passing *tgt to btrfs_get_block_group() will result in a NULL
pointer dereference, as btrfs_get_block_group() doesn't check for NULL.

Additionally, does check_bg_is_active() modify *tgt?

Because tgt is passed as a double pointer, check_bg_is_active() can modify
the underlying pointer (e.g., when activating a new block group it does
*active_bg = block_group).

If this happens, the subsequent btrfs_put_block_group(*tgt) will drop the
reference on the newly assigned block group instead of the one originally
acquired. This could lead to a leaked reference on the old block group and
a premature free on the new one.
