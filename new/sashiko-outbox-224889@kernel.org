>   - Error (ret < 0)

[Severity: Medium]
Does this still set cancelled to true when stopped is false?

The commit message notes that cancelled should only be updated if the
rescan is stopped, to handle a finished-then-cancelled rescan.  However,
because the outer condition starts with !stopped, this block is entered
whenever the scan loop finishes the last leaf (ret > 0 and stopped is
false).  If qgroup_mark_inconsistent() sets
BTRFS_QGROUP_RUNTIME_BIT_CANCEL_RESCAN before qgroup_rescan_lock is
taken here, btrfs_qgroup_rescan_worker() clears
BTRFS_QGROUP_STATUS_BIT_INCONSISTENT for ret > 0, but still sets
cancelled = true and logs "qgroup scan cancelled" instead of completion.

Setting cancelled = stopped &&
test_bit(BTRFS_QGROUP_RUNTIME_BIT_CANCEL_RESCAN, &fs_info->qgroup_flags)
before the if (!stopped || cancelled) check would avoid the duplicate
test_bit() and only record cancellation when the loop actually stopped.
