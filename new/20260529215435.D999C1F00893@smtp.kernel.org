btrfs: use lockless read in nr_cached_objects shrinker callback

This commit replaces the spinlock-protected percpu_counter_sum_positive call
with the lockless percpu_counter_read_positive in the btrfs shrinker callback
to prevent global serialization during memcg-driven slab reclaim.

[Severity: High]
This isn't a bug introduced by this patch, but modifying this exact line
highlights a pre-existing issue. Does btrfs_nr_cached_objects() need to
return 0 when called during memcg-specific reclaim (when sc->memcg != NULL)?

Since btrfs extent maps are global and lack the SLAB_ACCOUNT flag, returning
their global count during memcg-driven reclaim skews the proportions
calculated in super_cache_scan(). The global object count dominates the
target memcg's dentry and inode counts, effectively crushing the target scan
counts to 0.

This causes the shrinker to queue massive asynchronous work to drop global
extent maps, which doesn't free any memory for the constrained memcg. This
can lead to heavy global cache thrashing while the memcg reclaim loop spins
with minimal progress.
