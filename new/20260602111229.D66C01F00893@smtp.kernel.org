[Severity: High]
Will this dereference a NULL pointer on early mount failure paths?

When block devices are initially allocated and discovered (for example, via
btrfs_scan_one_device()), device->fs_info is initialized to NULL. It is
only assigned later in the mount sequence.

If the mount fails early before this initialization happens (such as from
an invalid superblock or a chunk tree read error), the cleanup path invokes
btrfs_close_devices() which calls btrfs_close_bdev(). Does accessing
device->fs_info->sb here cause a kernel panic on those error paths?
