btrfs: do not allow fast fsync if there is any async dio write

This commit sets BTRFS_INODE_NEEDS_FULL_SYNC on the inode when
btrfs_dio_write() returns -EIOCBQUEUED so that subsequent fsync() calls do
not use the fast path while an asynchronous direct write is in flight.

[Severity: High]
Can calling btrfs_set_inode_full_sync() here while holding only
BTRFS_ILOCK_SHARED race with a concurrent O_DSYNC/O_SYNC direct write on
the same inode?

btrfs_set_inode_full_sync() requires callers to hold either the exclusive
VFS inode lock or inode->i_mmap_lock so that BTRFS_INODE_NEEDS_FULL_SYNC
cannot change while btrfs_sync_file() is running.  For direct writes
within EOF, btrfs_direct_write() takes only BTRFS_ILOCK_SHARED and does
not take i_mmap_lock.  When a synchronous direct write completes via
iomap_dio_complete() -> generic_write_sync() -> btrfs_sync_file() with
current->journal_info set to BTRFS_TRANS_DIO_WRITE_STUB, btrfs_sync_file()
sets skip_ilock = true and only acquires inode->i_mmap_lock:

CPU0 (sync DIO write within EOF)  CPU1 (async DIO write within EOF)
btrfs_direct_write()              btrfs_direct_write()
  btrfs_inode_lock(..., SHARED)     btrfs_inode_lock(..., SHARED)
  iomap_dio_complete()              btrfs_dio_write()
    ...                               ...
    btrfs_sync_file()                 btrfs_dio_iomap_begin()
      down_write(&i_mmap_lock)        btrfs_dio_submit_io()
      full_sync = test_bit(...)
      /* full_sync is false, skips
         btrfs_wait_ordered_range() */
                                    btrfs_set_inode_full_sync()
      btrfs_log_dentry_safe()
        ...
        btrfs_log_inode()
          test_bit(NEEDS_FULL_SYNC) <-- now true!
          clear_bit(NEEDS_FULL_SYNC)
          copy_inode_items_to_log()
          /* skips btrfs_log_changed_extents()
             and purges modified_extents */

Because btrfs_log_inode() re-tests BTRFS_INODE_NEEDS_FULL_SYNC and
switches from fast_search to copying committed subvolume items without
btrfs_sync_file() having waited for ordered extents, CPU0's uncommitted
ordered extent is dropped from the log and removed from modified_extents,
breaking O_DSYNC durability on power loss and clearing
BTRFS_INODE_NEEDS_FULL_SYNC while CPU1's async bio is still in flight.

In addition, because CPU1 sets BTRFS_INODE_NEEDS_FULL_SYNC only after
btrfs_dio_write() returns -EIOCBQUEUED, if CPU0's skip_ilock
btrfs_sync_file() runs between CPU1's btrfs_dio_iomap_begin() and
btrfs_set_inode_full_sync(), CPU0 still observes full_sync == false and
logs CPU1's unwritten extent before its bio finishes.
