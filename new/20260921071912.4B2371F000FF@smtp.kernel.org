[Severity: Medium]
When the worker stops due to a freeze (via rescan_should_stop() or -EINTR),
stopped is set to true.

Later in btrfs_qgroup_rescan_worker(), there is this logic:

    if (!stopped || test_bit(BTRFS_QGROUP_RUNTIME_BIT_CANCEL_RESCAN,
                             &fs_info->qgroup_flags))
        clear_bit(BTRFS_QGROUP_STATUS_BIT_RESCAN, &fs_info->qgroup_flags);

Since stopped is true and CANCEL_RESCAN is false in the freeze case, the
BTRFS_QGROUP_STATUS_BIT_RESCAN bit is never cleared from memory, even though
the worker exits.

The commit message notes: "the end user/tool should re-start a rescan if they
need uptodate qgroup numbers."

However, if a user tries to restart the rescan, qgroup_rescan_init() checks
the bit:

    if (test_bit(BTRFS_QGROUP_STATUS_BIT_RESCAN, &fs_info->qgroup_flags) ||
        test_bit(BTRFS_QGROUP_RUNTIME_BIT_REJECT_RESCAN,
                 &fs_info->qgroup_flags)) {
        ret = -EINPROGRESS;
        goto err;
    }

Does this stale RESCAN bit cause subsequent attempts to restart the rescan to
fail with -EINPROGRESS, permanently locking the user out until a remount?
