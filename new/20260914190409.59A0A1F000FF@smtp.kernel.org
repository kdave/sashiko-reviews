btrfs: fix creation of compressed inline extents that don't save space

This commit modifies the inline extent creation logic to pass the inode's
i_size instead of blocksize to btrfs_compress_bio(), avoiding compression
when the data doesn't shrink. It also adds a preemptive check using
can_cow_file_range_inline() before attempting compression.

[Severity: High]
Does this preemptive check unintentionally reject valid compressible files?

Because 0 is passed for the compressed_size argument,
can_cow_file_range_inline() evaluates data_len using the uncompressed i_size.
Inside can_cow_file_range_inline(), there are checks that evaluate data_len
against sectorsize and max_inline:

	/* We do not allow a non-compressed extent to be as large as block size. */
	if (data_len >= fs_info->sectorsize)
		return false;

	/* We cannot exceed the user specified max_inline size. */
	if (data_len > fs_info->max_inline)
		return false;

When a file is exactly sectorsize (e.g., 4096 bytes) or its uncompressed size
is larger than max_inline (default 2048) but smaller than sectorsize, this
will return false preemptively. This appears to break inline compression for
these files, even if their data would successfully compress to a valid inline
size.

[Severity: High]
Does passing i_size instead of blocksize break LZO compression for inline
extents smaller than a sector?

When run_delalloc_inline() passes a length smaller than sectorsize down to
btrfs_compress_bio(), it propagates to LZO compression in
copy_compressed_data_to_bio() as max_out.

Looking at the boundary check in fs/btrfs/lzo.c:copy_compressed_data_to_bio():

		/* With the range copied, we're larger than the original range. */
		if (((*total_out + copy_len) >> sectorsize_bits) >=
		    max_out >> sectorsize_bits)
			return -E2BIG;

If i_size (and thus max_out) is less than a sector, max_out >> sectorsize_bits
evaluates to 0. Since the left side of the inequality is at least 0, this
check will unconditionally evaluate to true and return -E2BIG. This causes
LZO inline compression to fail completely for these files.
