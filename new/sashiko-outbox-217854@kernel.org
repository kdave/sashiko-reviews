[Severity: Medium]
Can concurrent callers race on the static buf[] in btrfs_sb_uuid_string()?
Neither btrfs_find_dev_by_spec() nor the exported find_dev_by_fs_spec() holds
a lock that serializes access to buf[], so concurrent lookups can overwrite
buf[] while strcasecmp() is comparing it.  Parsing value once with
uuid_parse() in btrfs_find_dev_by_spec() and comparing against
disk_super->fsid would avoid both the shared static buffer and formatting
every device's UUID.

[Severity: High]
Is it safe to read from bdev->bd_mapping without opening the block device
first via bdev_file_open_by_dev()?

blkdev_get_whole() and blkdev_get_part() only call set_init_blocksize() when
bd_openers transitions from 0 to 1:

block/bdev.c:blkdev_get_part() {
	...
	if (!atomic_read(&part->bd_openers)) {
		disk->open_partitions++;
		set_init_blocksize(part);
	}
	...
}

Reading bdev->bd_mapping while bd_openers is 0 populates order-0 pagecache
folios (and PAGE_SIZE buffer_heads) before set_init_blocksize() configures
i_blkbits and folio_min_order, and because the device is never closed, those
folios are not evicted.  When any probed device is later opened for the first
time, set_init_blocksize() changes i_blkbits and folio_min_order without
invalidating the mapping, leaving cached folios whose geometry conflicts with
the block device's configured blocksize.  Skipping open also bypasses
disk->open_mutex, disk->fops->open(), and partition scan synchronization.

[Severity: High]
Does wiring btrfs_find_dev_by_spec() to btrfs_fs_type.find_by_spec sleep
inside an RCU read-side critical section and invert the return value expected
by find_dev_by_fs_spec()?

fs/filesystems.c:find_dev_by_fs_spec() {
	...
	guard(rcu)();
	hlist_for_each_entry_rcu(p, &file_systems, list) {
		if (!(p->fs_flags & FS_REQUIRES_DEV) || !p->find_by_spec)
			continue;
		...
		if (!try_module_get(p->owner))
			continue;
		if (p->find_by_spec(key, value, &dev) && dev)
			break;
		module_put(p->owner);
	}
	...
}

find_dev_by_fs_spec() calls p->find_by_spec() under guard(rcu)(), while
btrfs_find_dev_by_spec() -> btrfs_dev_spec_matches() ->
btrfs_read_disk_super() takes the sleeping rw_semaphore
filemap_invalidate_lock_shared() and performs synchronous block I/O via
mapping_read_folio_gfp().  In addition, btrfs_find_dev_by_spec() returns 0 on
a match and negative errno on failure, whereas find_dev_by_fs_spec() checks
for a non-zero return value, so a match does not break out of the loop (and a
break on a non-zero return skips module_put(p->owner)).
