btrfs: use an on-stack path in btrfs_insert_orphan_item()

This commit changes btrfs_insert_orphan_item() to use an on-stack
btrfs_path rather than allocating one dynamically. This prevents a
memory allocation failure from turning into a transaction abort.

[Severity: High]
This isn't a bug introduced by this patch, but should btrfs_del_orphan_item()
also be updated to use an on-stack path?

Looking at btrfs_del_orphan_item() right below this function, it still
does a dynamic allocation:

int btrfs_del_orphan_item(...)
{
	...
	path = btrfs_alloc_path();
	if (!path)
		return -ENOMEM;

If an unprivileged user creates an O_TMPFILE and links it using linkat()
during memory pressure, this allocation can fail.

The error propagates up through btrfs_orphan_del() into btrfs_link(),
which then unconditionally aborts the transaction:

fs/btrfs/inode.c:btrfs_link() {
    ...
		ret = btrfs_orphan_del(trans, BTRFS_I(inode));
		if (unlikely(ret)) {
			btrfs_abort_transaction(trans, ret);
			goto fail;
		}
    ...
}

Could btrfs_del_orphan_item() be converted to use an on-stack path as well
to close this identical transaction abort vector?
