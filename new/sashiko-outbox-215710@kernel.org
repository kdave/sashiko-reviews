[Severity: High]
How does btrfs_read_locked_inode() distinguish an inode with a valid
ptime from a legacy or mkfs-created inode whose on-disk reserved[] field
was never initialized for ptime?

On existing Btrfs filesystems (and the root directory inode created by
mkfs.btrfs), reserved[] was zeroed, so inode->i_ptime_nsec is 0 (<
NSEC_PER_SEC).  btrfs_getattr() and btrfs_fileattr_get() then
unconditionally advertise STATX_PTIME and FS_XFLAG_PTIME with timestamp
{0, 0} (1970-01-01) instead of falling back to otime or omitting
STATX_PTIME.

Conversely, for inodes replayed from an older kernel's tree log where
btrfs_insert_empty_item() did not zero the leaf item and
tree-log.c:fill_inode_item() did not write reserved[], the on-disk ptime
field holds uninitialized leaf bytes.  Whenever the stale 32-bit nsec
word happens to be < NSEC_PER_SEC, btrfs_read_locked_inode() silently
loads arbitrary stale bytes into i_ptime_sec and i_ptime_nsec.  Mounting
the filesystem on an older kernel and updating the inode via
btrfs_delayed_update_inode() will also silently overwrite ptime with {0,
0} because nothing marks whether ptime is valid.

Does this fsx_xflags_mask check reject Btrfs-supported common xflags
(FS_XFLAG_SYNC, FS_XFLAG_IMMUTABLE, FS_XFLAG_APPEND, FS_XFLAG_NODUMP,

fileattr_has_fsx_mask() implicitly permits FS_XFLAG_COMMON in
fa->fsx_xflags, and fileattr_to_file_attr() includes FS_XFLAGS_MASK in
fa_xflags_mask on file_getattr().  Because BTRFS_SUPPORTED_XFLAGS only

common xflag in fa_xflags_mask—or passes back a struct file_attr filled

[Severity: High]
Does checking fa->flags on symlinks and special files both reject valid
ptime updates and allow clearing existing flags when fa->flags is 0?

When a symlink or special file is created in a directory with
BTRFS_INODE_COMPRESS, BTRFS_INODE_NOCOMPRESS, or BTRFS_INODE_NODATACOW,
btrfs_create_new_inode() -> btrfs_inherit_iflags() copies those flags to
the new inode regardless of mode.  When file_setattr() is later called to
update only FS_XFLAG_PTIME, vfs_fileattr_set() merges old_ma.flags &
~FS_COMMON_FL into fa->flags:

fs/file_attr.c:vfs_fileattr_set() {
    ...
	if (fa->fsx_valid) {
		err = vfs_fileattr_get(dentry, &old_ma);
		if (err)
			return err;
		fa->flags |= old_ma.flags & ~FS_COMMON_FL;
    ...
}

Because FS_COMPR_FL, FS_NOCOMP_FL, and FS_NOCOW_FL are not in
FS_COMMON_FL, fa->flags becomes non-zero and btrfs_fileattr_set()
rejects the ptime update with -EOPNOTSUPP.

Conversely, if a caller invokes FS_IOC_SETFLAGS with flags == 0 (or
FS_IOC_FSSETXATTR / file_setattr() with zero flags and without
FS_XFLAG_PTIME) on a symlink or special file, fa->flags is 0.
btrfs_fileattr_set() then proceeds to start a transaction, clear any
existing inode flags, update ctime/iversion, and return 0 instead of
-EOPNOTSUPP.
