btrfs: zoned: use the regular allocator for conventional metadata block groups

This commit switches metadata and system block groups backed solely by
conventional zones on zoned filesystems from the sequential zoned allocator
to the regular free space cache allocator. It replaces filesystem-wide
btrfs_is_zoned() checks in space accounting, free space tracking, and extent
allocation with per-block-group btrfs_zoned_bg_is_append_only() checks.

[Severity: Medium]
Can this cause a premature -ENOSPC regression in
find_free_extent_update_loop() when allocating metadata with a non-zero
empty_size hint?

With bg_alloc_policy() routing non-append-only block groups to
do_allocation_clustered() -> find_free_extent_unclustered(), the allocation
now honors ffe_ctl->empty_size:

fs/btrfs/extent-tree.c:find_free_extent_unclustered() {
    ...
	if (ffe_ctl->cached) {
		...
		if (free_space_ctl->free_space <
		    ffe_ctl->num_bytes + ffe_ctl->empty_cluster +
		    ffe_ctl->empty_size) {
			...
			return 1;
		}
		...
	}

	offset = btrfs_find_space_for_alloc(bg, ffe_ctl->search_start,
			ffe_ctl->num_bytes, ffe_ctl->empty_size,
			&ffe_ctl->max_extent_size);
    ...
}

Callers such as btrfs_realloc_node() -> btrfs_force_cow_block() ->
btrfs_alloc_tree_block() -> btrfs_reserve_extent() pass a non-zero
empty_size hint when allocating tree blocks during defragmentation.

If a conventional metadata block group has free extents of size nodesize
available, but no contiguous range (or total free space) of size
nodesize + empty_size, and chunk allocation cannot allocate a new metadata
chunk, find_free_extent() advances to LOOP_NO_EMPTY_SIZE.

However, ffe_ctl->policy remains set to BTRFS_EXTENT_ALLOC_ZONED, so
find_free_extent_update_loop() bails out immediately instead of clearing
ffe_ctl->empty_size and retrying for num_bytes alone:

fs/btrfs/extent-tree.c:find_free_extent_update_loop() {
    ...
	if (ffe_ctl->loop == LOOP_NO_EMPTY_SIZE) {
		if (ffe_ctl->policy != BTRFS_EXTENT_ALLOC_CLUSTERED)
			return -ENOSPC;

		if (ffe_ctl->empty_size == 0 && ffe_ctl->empty_cluster == 0)
			return -ENOSPC;
		ffe_ctl->empty_size = 0;
		ffe_ctl->empty_cluster = 0;
	}
    ...
}

Should find_free_extent_update_loop() allow dropping empty_size when
allocating from non-append-only block groups on zoned filesystems?
