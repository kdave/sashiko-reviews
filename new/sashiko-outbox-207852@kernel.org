[Severity: Critical]
This problem wasn't introduced by this patch, but can zstd_put_workspace()
trigger a use-after-free [1] on workspace when racing with
zstd_reclaim_timer_fn()?

fs/btrfs/zstd.c:zstd_put_workspace() {
    ...
	set_bit(workspace->level, &zwsm->active_map);
	list_add(&workspace->list, &zwsm->idle_ws[workspace->level]);
	workspace->req_level = 0;

	spin_unlock_bh(&zwsm->lock);

	if (workspace->level == clip_level(ZSTD_BTRFS_MAX_LEVEL))
		cond_wake_up(&zwsm->wait);
}

When zstd_find_workspace() borrows a higher-level workspace for a lower
compression level (clip_level(level) < workspace->level), the workspace
stays on zwsm->lru_list with its old workspace->last_used timestamp while
workspace->req_level is set.  If workspace->last_used ages past
ZSTD_BTRFS_RECLAIM_JIFFIES before the workspace is returned,
zstd_put_workspace() skips the LRU update, clears workspace->req_level and
unlocks zwsm->lock:

CPU0                              CPU1 (<softirq>)
zstd_put_workspace()
  spin_lock_bh(&zwsm->lock)
  workspace->req_level = 0
  spin_unlock_bh(&zwsm->lock)
                                  zstd_reclaim_timer_fn()
                                    spin_lock(&zwsm->lock)
                                    zstd_free_workspace(&victim->list)
                                      kfree(workspace)
                                    spin_unlock(&zwsm->lock)
  if (workspace->level == ...)  <-- use-after-free

Once zwsm->lock is released, zstd_reclaim_timer_fn() can see
victim->req_level == 0 with an expired last_used timestamp and free the
workspace before zstd_put_workspace() reads workspace->level.  Checking
workspace->level before unlocking zwsm->lock (or caching it in a local
variable) would avoid the race.
