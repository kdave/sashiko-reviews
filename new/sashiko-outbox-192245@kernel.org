[Severity: Medium]
When a caller invokes FS_IOC_SETFLAGS via ioctl_setflags(),
fileattr_fill_flags() sets fa->flags_valid = true. In vfs_fileattr_set(),
vfs_fileattr_get() populates old_ma.fsx_xflags with FS_XFLAG_PTIME and
old_ma.fsx_ptime with the current on-disk timestamp on filesystems that
support ptime:

	if (fa->flags_valid) {
		fa->fsx_xflags |= old_ma.fsx_xflags & ~FS_XFLAG_COMMON;
		...
		fa->fsx_ptime = old_ma.fsx_ptime;
	}

Because FS_XFLAG_PTIME is not in FS_XFLAG_COMMON, this copies FS_XFLAG_PTIME
into fa->fsx_xflags even though FS_IOC_SETFLAGS did not request a ptime
update.

As a result, fileattr_set_prepare() enters the FS_XFLAG_PTIME validation and
truncation block on every FS_IOC_SETFLAGS call:

1. On ntfs3 (introduced in "ntfs3: make crtime user-settable using ptime"),
   nt2kernel() computes tv_sec and tv_nsec via div_s64_rem(), which yields a
   negative tv_nsec for pre-1970 on-disk cr_time values with a non-zero
   sub-second remainder. Unrelated FS_IOC_SETFLAGS calls on such files will
   fail with -EINVAL at the (unsigned long)fa->fsx_ptime.tv_nsec >=
   NSEC_PER_SEC check.

2. If old_ma.fsx_ptime is modified by timestamp_truncate(fa->fsx_ptime, inode)
   (for instance when tv_sec is at sb->s_time_min or sb->s_time_max with a
   non-zero tv_nsec, or on exfat when timezone adjustment shifts tv_sec below
   EXFAT_MIN_TIMESTAMP_SECS), !timespec64_equal(&old_ma->fsx_ptime,
   &fa->fsx_ptime) becomes true. On immutable or append-only files (such as
   when toggling FS_NODUMP_FL with CAP_LINUX_IMMUTABLE while keeping
   FS_IMMUTABLE_FL or FS_APPEND_FL set), fileattr_set_prepare() rejects the
   FS_IOC_SETFLAGS call with -EPERM. On mutable files, filesystem callbacks
   that do not check !fa->flags_valid (such as ntfs_fileattr_set() and
   exfat_fileattr_set()) will overwrite the on-disk creation time with the
   truncated timestamp.

Should vfs_fileattr_set() avoid setting FS_XFLAG_PTIME in fa->fsx_xflags (or
should fileattr_set_prepare() and filesystem callbacks ignore FS_XFLAG_PTIME)
when fa->flags_valid is true?
