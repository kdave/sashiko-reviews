[Severity: High]
Does returning -EUCLEAN for unknown sizes, versions, and flags prevent
graceful degradation on older kernels?

If a filesystem is used on a newer kernel that adds a new qgroup flag or
expands the item size without adding an incompat bit, mounting it on this
kernel would fail completely. The tree checker intercepts the quota tree
root read during mount and returns -EUCLEAN, which aborts the mount process.

Previously, btrfs_read_qgroup_config() handled unexpected versions by logging
a message and disabling quotas, allowing the mount to proceed. Should the
tree checker avoid strict checks on feature flags and exact sizes unless
they are protected by incompat bits?
