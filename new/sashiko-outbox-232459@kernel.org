[Severity: High]
This problem wasn't introduced by this patch, but can
btrfs_tree_block_level(leaf, info) read past the extent item and extent
buffer [1] because ptr + sizeof(*info) <= end is never checked?

check_extent_item() only verifies item_size >= sizeof(*ei) before reading
info->level on a BTRFS_EXTENT_ITEM_KEY tree block.  If a corrupted item at
slot 0 is smaller than sizeof(*ei) + sizeof(*info), info->level lies past
leaf->len, and btrfs_get_8() indexes eb->folios[] before checking
member_offset + sizeof(u8) > eb->len:

fs/btrfs/accessors.c:btrfs_get_8() {
	const unsigned long member_offset = (unsigned long)ptr + off;
	const unsigned long idx = get_eb_folio_index(eb, member_offset);
	const unsigned long oif = get_eb_offset_in_folio(eb,
							 member_offset);
	char *kaddr = folio_address(eb->folios[idx]) + oif;
	...
	if (unlikely(member_offset + sizeof(u8) > eb->len)) {

This dereferences an unpopulated eb->folios[idx] entry and panics the
kernel.
