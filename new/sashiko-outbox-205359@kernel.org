> btrfs: zoned: don't release active zone reservations for conventional zones
>
> On mount, btrfs_check_active_zone_reservation() releases a reserved
> active zone for each stripe of an active metadata or system block-group.
> Block-groups on conventional zones are marked active when loaded but
> hold no active zone on the device, so they use up the reservation. Once
> metadata moves to a sequential block-group, its activation fails and the
> transaction commit aborts with -EAGAIN.
>
> Only release reservations for sequential zones.
>

[Severity: Medium]
Can skipping conventional stripes here cause a reservation mismatch with
btrfs_zone_activate() and call_zone_finish() on a multi-stripe block group
that spans both a conventional zone and a sequential zone?

When loading a partly conventional DUP or RAID metadata/system block group
whose sequential stripe is open, btrfs_load_block_group_dup() sees
test_bit(0, active) != test_bit(1, active) and calls
btrfs_zone_activate().  Neither btrfs_zone_activate() nor
btrfs_dev_set_active_zone() checks btrfs_dev_is_sequential():

fs/btrfs/zoned.c:btrfs_zone_activate() {
    ...
		if (!btrfs_dev_set_active_zone(device, physical, &new)) {
			/* Cannot activate the zone */
			ret = false;
			goto out_unlock;
		}
		if (!is_data && new)
			zinfo->reserved_active_zones--;
    ...
}

For the conventional stripe, btrfs_dev_set_active_zone() decrements
zone_info->active_zones_left and sets the zone bit in
zone_info->active_zones.  btrfs_check_active_zone_reservation() then
resets reserved_active_zones and, with this patch, skips the conventional
stripe while leaving its bit set in zone_info->active_zones.  When the
block group is later finished in do_zone_finish() -> call_zone_finish(),
btrfs_dev_clear_active_zone() clears that bit and increments
zinfo->reserved_active_zones++, permanently over-counting
reserved_active_zones and starving data block groups of active zones.

Likewise, activating a partly conventional metadata or system block group
at runtime via btrfs_zone_activate() still consumes active_zones_left and
decrements reserved_active_zones for the conventional stripe.
