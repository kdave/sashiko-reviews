btrfs: fix use-after-free on reloc root after error in insert_dirty_subvol()

This commit attempts to fix a use-after-free during unmount by ensuring that
failed subvolume roots are added to the dirty_subvol_roots list. This is
intended to allow clean_dirty_subvols() to clear the root->reloc_root pointer
if btrfs_update_reloc_root() fails.

[Severity: Critical]
Does this change shift the use-after-free from unmount time to an earlier point
during error recovery?

By unconditionally adding the root to dirty_subvol_roots, the root will be
processed by clean_dirty_subvols() later in relocate_block_group().

As noted in the commit message's step 4, the reloc_root is already freed by
free_reloc_roots() in merge_reloc_roots() during error handling. When
clean_dirty_subvols() later processes this list, it sets root->reloc_root to
NULL, but then it immediately passes the previously saved and already freed
reloc_root pointer to btrfs_drop_snapshot():

Since btrfs_drop_snapshot() dereferences reloc_root, will this cause an
