[Severity: Low]
Can this result in an uninitialized value read?

If a user calls FS_IOC_SETFLAGS (e.g., via chattr +c) on a file that lacks a
compression property, this code will unconditionally read
inode->prop_compress_level and pass it by value.

During inode allocation, this field is left uninitialized:

fs/btrfs/inode.c:btrfs_alloc_inode() {
    ...
    ei->runtime_flags = 0;
    ei->prop_compress = BTRFS_COMPRESS_NONE;
    ei->defrag_compress = BTRFS_COMPRESS_NONE;

    ei->delayed_node = NULL;
    ...
}

Passing uninitialized slab memory by value triggers KMSAN warnings
(uninit-value). Even though the value is ultimately ignored when
prop_compress is NONE, could this undefined behavior break sanitizer builds?
