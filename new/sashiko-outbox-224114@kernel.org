[Severity: High]
Does taking bg->alloc_offset from highest leave
BLOCK_GROUP_FLAG_ZONE_IS_ACTIVE out of sync with the write pointer when
the stripes' active states differ on a degraded mount?

On a degraded mount, btrfs_zone_activate() is skipped when
test_bit(first, active) != test_bit(i, active), and
BLOCK_GROUP_FLAG_ZONE_IS_ACTIVE is only set when test_bit(first, active)
is true.  If the first present stripe is behind at offset 0
(BLK_ZONE_COND_EMPTY, inactive) while another stripe is partially written
(0 < alloc_offset < capacity, active), bg->alloc_offset is set to highest
(> 0), so btrfs_load_block_group_zone_info() sets
bg->meta_write_pointer = bg->start + highest while leaving
BLOCK_GROUP_FLAG_ZONE_IS_ACTIVE clear and omitting the block group from
fs_info->zone_active_bgs:

fs/btrfs/zoned.c:btrfs_zone_activate() {
	...
	if (block_group->flags & BTRFS_BLOCK_GROUP_DATA) {
		...
	} else {
		/* Since it is already written, it should have been active. */
		WARN_ON_ONCE(block_group->meta_write_pointer != block_group->start);
	}
}

For a metadata block group, the next btrfs_zone_activate() call triggers
that WARN_ON_ONCE, and btrfs_check_active_zone_reservation() fails to
account for the active zone on the ahead stripe.  For a data block group
(or when the first stripe is full and another stripe is partially
written), relocating the block group during balance skips do_zone_finish()
because BLOCK_GROUP_FLAG_ZONE_IS_ACTIVE is clear, leaking the active zone
on the partially written stripe.  Conversely, if the first stripe is
active and a later stripe is empty, iteration i == first sets
BLOCK_GROUP_FLAG_ZONE_IS_ACTIVE without activating the empty stripe's
zone in device->zone_info, so subsequent writes open that zone in
hardware without decrementing active_zones_left.
