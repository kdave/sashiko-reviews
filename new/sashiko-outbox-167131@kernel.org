btrfs: prevent use-after-free in btrfs_transaction::switch_commits

This commit prevents a use-after-free during transaction aborts by manually
deleting all entries from the switch_commits list during cleanup. It also
releases dirty_log_pages and qgroup swapped blocks for roots on that list,
which are otherwise only cleaned up during a successful switch_commit_roots().

[Severity: Medium]
Will this leak swapped_blocks and dirty_log_pages on an early transaction
abort?

The patch attempts to fix a resource leak by adding this cleanup block, but
strictly limits the cleanup to roots that reached the switch_commits list.

If the transaction aborts earlier in btrfs_commit_transaction(), for example
during create_pending_snapshots() or btrfs_run_delayed_items(), it will skip
commit_fs_roots():

fs/btrfs/transaction.c:btrfs_commit_transaction() {
        ...
        ret = create_pending_snapshots(trans);
        if (unlikely(ret))
                goto unlock_reloc;
        ...
        ret = commit_fs_roots(trans);
        if (unlikely(ret))
                goto unlock_reloc;
        ...
}

In this scenario, the dirtied subvolume roots are never added to the
switch_commits list.

Because the cleanup loop in btrfs_cleanup_one_transaction() only traverses
switch_commits, any root not on that list will bypass
btrfs_extent_io_tree_release() and btrfs_qgroup_clean_swapped_blocks().

When the root is ultimately destroyed in btrfs_put_root(), the final teardown
does not clean up these resources:

fs/btrfs/disk-io.c:btrfs_put_root() {
        ...
                free_root_extent_buffers(root);
        ...
                kfree(root);
}

Does this leave the swapped_blocks and dirty_log_pages allocated forever
when the abort happens early in the commit path?
