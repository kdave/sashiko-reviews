accounting transfer to allow reserving the data relocation block group at

[Severity: Medium]
Does advancing start = bg->start + bg->length and filtering with
tmp->start < start assume bg_list is sorted by ascending start address?

zoned_move_bg_to_space_info() moves block groups using list_move_tail(),
so any block group with a lower start address that is moved back from
reloc_sinfo to data_sinfo sits at the tail of data_sinfo->block_groups[index]
after block groups with higher start addresses.  If an earlier entry with
a higher start address fails btrfs_set_data_reloc_bg(), retrying with
start = bg->start + bg->length skips all lower-addressed empty block
groups later in the list.

In addition, if btrfs_set_data_reloc_bg() fails because
btrfs_inc_block_group_ro_notrans() returned -ENOSPC (data_sinfo's free
space is already committed to reservations), every other empty block group
in data_sinfo has the same zone_capacity and will fail the same check, so
looping over all M empty block groups rescans bg_list in O(M * N) time
before falling through to chunk allocation.
