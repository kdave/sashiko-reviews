[Severity: High]
Could this single encompassing reservation create a metadata deficit that
leads to ENOSPC during writeback?

btrfs_delalloc_reserve_space() is called here for the entire range 
[start, start+len]. This reserves physical metadata space (in
block_rsv->reserved) for a minimal number of extents based on a contiguous
range.

However, defrag_collect_targets() may populate the target list with
multiple disjoint subranges if there are holes, skipped older extents, or
un-defragable extents within the range.

When EXTENT_DELALLOC is set on these individual disjoint fragments,
btrfs_mod_outstanding_extents() increments outstanding_extents and
block_rsv->size for each fragment independently.

Because the actual reserved metadata bytes (block_rsv->reserved) are never
increased beyond the initial contiguous reservation, block_rsv->size could
grow strictly larger than block_rsv->reserved.

Later, btrfs_delalloc_release_extents(inode, len) decrements based on the
single contiguous calculation, leaving a net increase in outstanding_extents
that is unfunded. Will this cause ENOSPC errors during tree block
allocation for these dirty extents?
