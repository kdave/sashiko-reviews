btrfs: zoned: track only sequential zones as active

This patch modifies active-zone tracking to strictly apply to sequential
zones, ensuring that active zone counters do not diverge across remounts.
It restricts active-zone bitmap and reservation updates to sequential
stripes to avoid exhausting slots for data operations.

[Severity: High]
This isn't a bug introduced by this patch, but is a pre-existing issue with
how we handle reserved active zones when activation fails.

If btrfs_zone_activate() fails midway through its stripe loop (for example,
due to active zone limits), it aborts without rolling back the already
activated stripes. When callers like check_bg_is_active() retry the 
activation on the same multi-stripe block group, btrfs_dev_set_active_zone()
will trivially succeed for the previously activated stripes. 

However, the loop continues and unconditionally executes the decrement for
non-data block groups:

        if (!is_data)
                zinfo->reserved_active_zones--;

Could this double-decrement permanently lower the reserved_active_zones 
counter? If the counter drops below zero, data block groups could bypass the
reservation limit and exhaust all active zone slots. This might prevent 
metadata block groups from activating during synchronous transaction 
writeback, forcing a transaction abort and a read-only filesystem.

[Severity: High]
This is a pre-existing issue, but does this increment in call_zone_finish()
introduce a data race with the decrement in btrfs_zone_activate()?

In btrfs_zone_activate(), the counter is decremented while holding the
fs_info->zone_active_bgs_lock. Concurrently, call_zone_finish() can run
asynchronously (such as from background zone finishing) and increment
this same counter without holding the zone_active_bgs_lock.

Since reserved_active_zones is a plain integer, can concurrent 
read-modify-write operations clobber each other? This drift could lead 
to either transaction aborts if the counter drops too low, or artificial 
deadlocks for data block groups if it goes too high.
