[Severity: High]
Will this trigger false positive BUG messages for legitimate requests
delayed in the workqueue?

When a loop device is closed, lo_release() sets lo_state = Lo_rundown and
then calls drain_workqueue(). The drain_workqueue() function legitimately
processes I/O that was queued before the teardown started.

Because loop_check_io_race() is called here from the asynchronous worker
thread during drain_workqueue(), won't it incorrectly flag these previously
queued requests as races?
