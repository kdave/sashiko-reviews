btrfs: move WARN_ON on unexpected error in __add_tree_block()

This commit moves the WARN_ON() check into the if condition when checking
for unexpected errors. This is intended to mark the branch as unlikely and
prevent the stack trace from obscuring the dumped leaf in the logs.

> diff --git a/fs/btrfs/relocation.c b/fs/btrfs/relocation.c
> --- a/fs/btrfs/relocation.c
> +++ b/fs/btrfs/relocation.c
> @@ -3187,13 +3187,12 @@ static int __add_tree_block(struct reloc_control *rc,
>  			goto again;
>  		}
>  	}
> -	if (ret) {
> +	if (WARN_ON(ret)) {

[Severity: Medium]
If panic_on_warn is enabled (which is standard in CI and fuzzing 
environments), will this cause the kernel to panic before printing the 
critical debugging information? 

Since the WARN_ON(ret) is evaluated in the condition, it executes before
btrfs_print_leaf() and btrfs_err(). The original code printed the leaf and
error message before triggering the warning, ensuring the state was logged
even if the system subsequently panics.
