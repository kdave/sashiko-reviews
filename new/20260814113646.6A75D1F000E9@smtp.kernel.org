btrfs: free qgroup configuration when quota enable fails

This commit updates the error path in btrfs_quota_enable() to use
btrfs_free_qgroup_config(). This ensures that in-memory qgroups and their
relations are properly cleaned up alongside sysfs entries if enabling quotas
fails.

> diff --git a/fs/btrfs/qgroup.c b/fs/btrfs/qgroup.c
> index 502fb4a55cb22..8f59a0e3b4f50 100644

>  		btrfs_put_root(quota_root);

[Severity: High]
This is a pre-existing issue, but while looking at the error handling in
btrfs_quota_enable(), I noticed a potential problem in the preallocation
failure path.

If kzalloc_obj() for prealloc fails with -ENOMEM:

	prealloc = kzalloc_obj(*prealloc, GFP_NOFS);
	if (!prealloc) {
		ret = -ENOMEM;
		goto out_free_path;
	}

Could jumping to out_free_path without calling btrfs_abort_transaction()
first commit a partial transaction, resulting in silent quota accounting
corruption?

Should we add a call to btrfs_abort_transaction(trans, ret) before the
goto?

>  	mutex_unlock(&fs_info->qgroup_ioctl_lock);
>  	if (ret && trans)
>  		btrfs_end_transaction(trans);
