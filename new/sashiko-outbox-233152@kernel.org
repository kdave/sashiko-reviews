btrfs: zoned: reject dev-replace onto a target with different zone types

This commit rejects device replacement on zoned filesystems if the target
device has fewer zones than the source device or a different sequential
zone bitmap layout.

[Severity: Medium]
Can bitmap_equal() read past the end of src_zinfo->seq_zones when
num_zones exceeds src_zinfo->nr_zones?

btrfs_get_dev_zone_info() allocates src_zinfo->seq_zones with
src_zinfo->nr_zones bits when the source device is opened, while
btrfs_grow_device() can later increase srcdev->total_bytes without
updating src_zinfo->nr_zones or reallocating src_zinfo->seq_zones.  If a
grown source device is then replaced with a target device large enough to
pass the device->zone_info->nr_zones < num_zones check, bitmap_equal()
reads out of bounds on src_zinfo->seq_zones.
