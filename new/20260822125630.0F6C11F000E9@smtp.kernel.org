[Severity: High]
Does this logic permanently hide surplus max-level workspaces from the reclaim
timer?

If there are multiple max-level workspaces and they are borrowed by concurrent
lower-level reads, they can bypass the LRU linkage when returned.

For example, if two lower-level reads borrow two max-level workspaces (W1 and
W2), the idle list for the max level becomes empty. When the first read returns
W1, the idle list is empty, so W1 hits the first condition, gets unlinked from
the LRU, and is added to the idle list.

When the second read returns W2, the idle list is no longer empty, so it falls
through to the else-if block. Since it was borrowed by a lower-level read,
clip_level(workspace->req_level) does not equal workspace->level, and the
block is skipped. W2 is never re-added to the LRU list.

Over time, this can act as a one-way ratchet, converting all ON-LRU workspaces
into OFF-LRU workspaces, which keeps these large workspaces pinned in memory
forever.
