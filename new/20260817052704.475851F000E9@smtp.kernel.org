btrfs: fix the possible bioc_list memory leak during error

This commit addresses memory leaks in the bioc_list of a btrfs_ordered_extent
by introducing btrfs_cleanup_ordered_bioc_list(). It ensures that all bioc
entries are properly removed and released, both during RAID extent insertion
and before the final release of the ordered extent.

[Severity: High]
This isn't a bug introduced by this patch, but is it possible for an error in
btrfs_insert_one_raid_extent() to cause a use-after-free and double-free of
the transaction handle?

If kzalloc() fails in btrfs_insert_one_raid_extent(), it prematurely ends
the transaction:

fs/btrfs/raid-stripe-tree.c:btrfs_insert_one_raid_extent() {
    ...
	stripe_extent = kzalloc(item_size, GFP_NOFS);
	if (unlikely(!stripe_extent)) {
		btrfs_abort_transaction(trans, -ENOMEM);
		btrfs_end_transaction(trans);
		return -ENOMEM;
	}
    ...
}

The error then propagates up to btrfs_finish_one_ordered(), which will
dereference the already-freed handle in btrfs_abort_transaction() and then
attempt to free it a second time at the out label:

fs/btrfs/inode.c:btrfs_finish_one_ordered() {
    ...
	ret = btrfs_insert_raid_extent(trans, ordered_extent);
	if (unlikely(ret)) {
		btrfs_abort_transaction(trans, ret);
		goto out;
	}
    ...
out:
    ...
	if (trans)
		btrfs_end_transaction(trans);
    ...
}

btrfs_insert_one_raid_extent() be removed since the caller handles aborting
