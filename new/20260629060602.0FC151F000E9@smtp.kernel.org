Subject: btrfs: use kvmalloc() for stripe buffer of scrub_stripe

This commit replaces the scrub_stripe folios array with a single kvmalloc'd
buffer to cover the full stripe. This aims to simplify checksum verification,
RAID56 data caching, and bio assembly by avoiding cross-page handling when
possible.

[Severity: Critical]
Could this code compute the wrong page offset when setting up the bio vector?

If kvmalloc falls back to kmalloc (which is possible since GFP_NOFS is used),
the allocation might not be perfectly page-aligned if KASAN or SLUB redzones
are enabled.

By passing offset_in_page(offset) instead of 
offset_in_page(stripe->buffer + offset), the bio vector will miss the base 
offset of the kmalloc'd buffer.

This could cause DMA to read or write the wrong data at the beginning of the
underlying physical page, potentially corrupting adjacent SLUB metadata or
memory.
