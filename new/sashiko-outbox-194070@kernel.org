[Severity: Medium]
Does this test need a _require_non_zoned_device $SCRATCH_DEV check before
mounting with -o nodatacow?

On a zoned btrfs filesystem, check_fsflags_compatible() in fs/btrfs/ioctl.c
only rejects FS_NOCOW_FL (+C), so both _require_chattr c and _require_chattr A
succeed. When the test then calls _scratch_mount "-o nodatacow", the kernel
rejects the mount with -EINVAL in btrfs_check_mountopts_zoned():

fs/btrfs/zoned.c:btrfs_check_mountopts_zoned() {
	if (btrfs_raw_test_opt(*mount_opt, NODATACOW)) {
		btrfs_err(info, "zoned: NODATACOW not supported");
		return -EINVAL;
	}
}

Without _require_non_zoned_device, running tests/btrfs/364 on a zoned block
device will fail during _scratch_mount instead of skipping with _notrun.

[Severity: Low]
This isn't a runtime bug since setting either attribute triggers
btrfs_fileattr_set() and check_fsflags(), but the commit message, test header
comment, and the comment above all describe +A as write append-only mode.

In chattr, +A sets no-atime updates (FS_NOATIME_FL), while +a sets
append-only mode (FS_APPEND_FL). Should the comments and commit message refer
to no-atime updates, or was _require_chattr a and $CHATTR_PROG +a intended
here?
