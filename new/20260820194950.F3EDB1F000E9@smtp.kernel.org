btrfs: Use filemap_invalidate_pages()

This patch replaces invalidate_inode_pages2() and
invalidate_inode_pages2_range() with filemap_invalidate_pages() to
perform bulk writeback before removing the page cache, removing the
need for btrfs_launder_folio().

[Severity: Critical]
Does this introduce synchronous writeback during transaction aborts?

In teardown paths like btrfs_destroy_delalloc_inodes(), Btrfs intends to
forcefully discard dirty pages. Because filemap_invalidate_pages() calls
filemap_write_and_wait_range(), it attempts to write back these pages instead.

Furthermore, if the writeback fails (which is likely during a transaction
abort), filemap_invalidate_pages() returns early and skips the actual page
invalidation. This leaves dirty pages stranded in memory and prevents inode
eviction.

[Severity: Critical]
Can this cause deadlocks during block group IO error cleanup?

Similar to the delalloc teardown path, btrfs_cleanup_bg_io() handles error
recovery and shouldn't attempt writeback. Initiating I/O here instead of
forcefully dropping the cache can result in massive unnecessary I/O and
potential deadlocks.

[Severity: Critical]
Is it safe to retry writeback in this error path?

This block executes when __btrfs_write_out_cache() has already encountered
an error (ret != 0). Calling filemap_invalidate_pages() synchronously attempts
writeback again. If this predictably fails, it skips page invalidation and
strands the pages in memory.
