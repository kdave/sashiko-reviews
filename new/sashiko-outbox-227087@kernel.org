[Severity: High]
Does excluding BTRFS_BLOCK_GROUP_DATA here leave BLOCK_GROUP_FLAG_ZONE_IS_ACTIVE
out of sync with per-device active zone tracking for RAID1 data block
groups on degraded mounts?

On iteration i == first, the loop sets BLOCK_GROUP_FLAG_ZONE_IS_ACTIVE
whenever the first present stripe is active, and skips
btrfs_zone_activate() on later stripes when DEGRADED is set.  For a data
block group with a write pointer mismatch, this breaks active zone
accounting in both directions:

If the first present stripe is partially written (active) and a later
stripe is behind at offset 0 (empty and inactive),
BLOCK_GROUP_FLAG_ZONE_IS_ACTIVE is set on the first iteration.  When data
is later allocated in bg, btrfs_zone_activate() sees
BLOCK_GROUP_FLAG_ZONE_IS_ACTIVE already set and returns true without
checking active_zones_left or calling btrfs_dev_set_active_zone() for the
empty stripe.  Subsequent zone append writes implicitly open that zone in
hardware without accounting it in device->zone_info->active_zones or
active_zones_left, which can exceed the device's max_active_zones limit
(failing writes with BLK_STS_ZONE_ACTIVE_RESOURCE) or consume active zones
reserved for metadata.

Conversely, if the first present stripe is inactive (either full at
zone_capacity, or empty at 0) while a later stripe is partially written
(active), BLOCK_GROUP_FLAG_ZONE_IS_ACTIVE remains clear and
btrfs_load_block_group_zone_info() does not add bg to
fs_info->zone_active_bgs, even though btrfs_get_dev_zone_info() already
counted the active stripe against its device's active_zones_left.  Because
do_zone_finish() returns early when BLOCK_GROUP_FLAG_ZONE_IS_ACTIVE is not
set:

fs/btrfs/zoned.c:do_zone_finish() {
	...
	spin_lock(&block_group->lock);
	if (!test_bit(BLOCK_GROUP_FLAG_ZONE_IS_ACTIVE, &block_group->runtime_flags)) {
		spin_unlock(&block_group->lock);
		return 0;
	}
	...
}

neither btrfs_zone_finish_one_bg() nor btrfs_zone_finish_relocated()
during balance can finish the open zone on the partially written stripe,
leaking its active zone slot (and if the first stripe was empty and that
later stripe holds the last unreserved active zone on its device,
btrfs_zone_activate() will also fail the active_zones_left <= reserved
check before btrfs_dev_set_active_zone() can see that the zone is already
active).
