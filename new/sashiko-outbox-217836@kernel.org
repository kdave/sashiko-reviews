Can this btrfs_warn() read uninitialized fields from res if end elapses

[Severity: Medium]
Does this miscount opened non-btrfs block devices as unreachable?

When btrfs_scan_one_device() opens the /dev node with
bdev_file_open_by_path() and btrfs_read_disk_super() finds no btrfs magic,
btrfs_scan_one_device() returns ERR_PTR(-EINVAL).  The IS_ERR(device)
branch here treats that -EINVAL the same as a missing /dev node: it leaves
opened unincremented (so res->opened always equals res->found) and records
the non-btrfs partition in res->unreachable and res->first_unreachable.
If only non-btrfs partitions are present on the first pass,
btrfs_wait_for_devices() sees !res.opened, warns that /dev nodes are
missing, and aborts the wait immediately.

[Severity: Medium]
Can is_root_dev() and root_wait trigger btrfs_wait_for_devices() on mounts
outside prepare_namespace()?

create_dev("/dev/root", ROOT_DEV) creates /dev/root with the same dev_t as
the underlying block device (e.g. /dev/sda1), and btrfs_get_tree_super()
checks is_root_dev(device->devt) while both ROOT_DEV and root_wait remain
set after boot (or when an initramfs is used and prepare_namespace() is
skipped).  Any later non-degraded mount of a btrfs filesystem on that
dev_t when a partner device is missing will enter btrfs_wait_for_devices()
and block (indefinitely under a bare rootwait), contradicting the
documented behavior that the search is only made during the root mount.
