btrfs: wait for ordered extent IO in fast fsync

This commit removes BTRFS_INODE_COW_WRITE_ERROR and instead has fast fsync
wait for BTRFS_ORDERED_IO_DONE on the collected ordered extents, checking
whether any COW ordered extent has BTRFS_ORDERED_IOERR set so it can wait
for ordered extent completion before logging.

[Severity: High]
Should cow_write_failed() in fs/btrfs/file.c also check
BTRFS_ORDERED_TRUNCATED in addition to BTRFS_ORDERED_IOERR?

When a COW (or PREALLOC) direct IO write stops short or fails before bio
submission (for example with -EFAULT when pinning user pages in
iomap_dio_bio_iter()), btrfs_dio_iomap_end() in fs/btrfs/direct-io.c does
not set BTRFS_ORDERED_IOERR on the unsubmitted ordered extent. Instead,
since commit 66ff4d366e7e ("btrfs: mark ordered extents in
btrfs_dio_iomap_end() truncated not ioerr"), it marks the ordered extent
truncated and finishes it with uptodate = true:

	if (dio_data->ordered) {
		btrfs_mark_ordered_extent_truncated(dio_data->ordered, 0);
		btrfs_finish_ordered_extent(dio_data->ordered,
					    pos + written, length - written, true);
	}

Similarly, extent_writepage_io() in fs/btrfs/extent_io.c sets
BTRFS_ORDERED_TRUNCATED and calls btrfs_mark_ordered_io_finished(..., true)
for sectors at or beyond i_size.

Because uptodate is true, can_finish_ordered_extent() sets
BTRFS_ORDERED_IO_DONE without setting BTRFS_ORDERED_IOERR. However, the
extent map for the unwritten range remains in inode->extent_tree and
inode->extent_tree.modified_extents until btrfs_finish_one_ordered() runs
in the workqueue:

	if (ret || truncated) {
		u64 unwritten_start = start;
		...
		if (truncated && !ret)
			unwritten_start += logical_len;
		btrfs_drop_extent_map_range(inode, unwritten_start, end, false);
	}

If a fast fsync runs in btrfs_sync_file() before btrfs_finish_one_ordered()
executes in the workqueue, cow_write_failed() sees BTRFS_ORDERED_IO_DONE
set and BTRFS_ORDERED_IOERR clear, returning false. Would that allow
btrfs_sync_file() to skip btrfs_wait_ordered_range() and log file extent
items pointing to the unwritten disk blocks before
btrfs_finish_one_ordered() drops and frees them?
