[Severity: Medium]
Does this lockless read pair correctly with the writer?

Looking at caching_thread() in fs/btrfs/block-group.c, the writer uses a plain
store for block_group->cached:

fs/btrfs/block-group.c:caching_thread() {
    ...
	spin_lock(&block_group->lock);
	block_group->caching_ctl = NULL;
	block_group->cached = ret ? BTRFS_CACHE_ERROR : BTRFS_CACHE_FINISHED;
	spin_unlock(&block_group->lock);
    ...
}

Because the writer does not use smp_store_release(), the surrounding spin_lock
does not prevent the CPU from reordering the store before earlier free_space
updates.

If the execution is reordered such that cached = FINISHED becomes globally
visible before the free_space updates, couldn't a concurrent reader using
smp_load_acquire() see FINISHED but read a stale free_space value and
incorrectly skip a block group with sufficient space?
