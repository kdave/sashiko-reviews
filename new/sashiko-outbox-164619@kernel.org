[Severity: Medium]
Does this code introduce a regression that leaks qgroup swapped blocks
during a transaction abort?

If a transaction is aborted while qgroups are enabled and block relocation
is ongoing, this loop unlinks roots from switch_commits but fails to
perform the btrfs_qgroup_clean_swapped_blocks() teardown that
switch_commit_roots() normally guarantees for roots on this list.

When the roots are eventually freed by btrfs_put_root(), the memory
allocated for struct btrfs_qgroup_swapped_block will leak because
btrfs_put_root() does not clean them up.

Could we invoke btrfs_qgroup_clean_swapped_blocks(root) before unlinking
the root here?
