behavior. It performs buffered writes of varying sizes and uses cachestat

[Severity: Medium]
Does splitting the buffered write and cachestat check into two separate xfs_io
invocations introduce a race condition?

When the first xfs_io process exits, the file descriptor is closed. Before
the second xfs_io process executes cachestat, kernel background writeback
could flush the dirtied pages to disk. This would cause cachestat to report
fewer dirty pages than expected and fail the test. 

Could these be combined into a single xfs_io invocation?

> +
> +	# Test dirty page number reporting after a fsync.
> +	$XFS_IO_PROG -c "fsync" -c "cachestat 0 $size" $SCRATCH_MNT/foobar
> +done
> +
> +_scratch_unmount
> +_exit 0

[Severity: High]
Is _exit 0 a valid bash command?

It looks like this will print "_exit: command not found" to stderr, which
will cause the test to systematically fail since fstests strictly compares
stderr output against the golden file.

Should this be exit 0 or just omitted?
