btrfs: always return -EIOCBQUEUED after btrfs_uring_read_extent_endio

This commit fixes a double free in the io_uring encoded read path by always
returning -EIOCBQUEUED instead of the I/O status when bios finish early.
This ensures only the deferred path cleans up the resources.

[Severity: High]
This isn't a bug introduced by this patch, but I have a question about how the
caller handles errors when propagating negative error codes.

In fs/btrfs/ioctl.c:btrfs_uring_encoded_read(), if import_iovec() allocates
a new array for data->iov, and a subsequent call to btrfs_uring_read_extent()
returns a negative errno (like -ENOMEM), the code jumps to out_acct:

fs/btrfs/ioctl.c:btrfs_uring_encoded_read() {
    ...
    ret = btrfs_uring_read_extent(kiocb, iter, &args, iov_iter_count(iter), data);
    if (ret < 0)
        goto out_acct;
    ...
out_acct:
    ...
    return ret;
out_free:
    kfree(data->iov);
    kfree(data);
    ...
}

Does this bypass the out_free label and leak the dynamically allocated
data->iov array when an error is returned?

[Severity: High]
This is also a pre-existing issue, but I'm curious about the cancellation path
for these requests when returning -EAGAIN from this call chain.

In the same caller, when returning -EAGAIN, the data structure is intentionally
kept so it can be reused on retry:

fs/btrfs/ioctl.c:btrfs_uring_encoded_read() {
    ...
    if (ret != -EIOCBQUEUED && ret != -EAGAIN) {
        kfree(data->iov);
        kfree(data);
    }
    ...
}

fs/btrfs/ioctl.c:btrfs_uring_encoded_write() {
    ...
    if (ret != -EAGAIN) {
        kfree(data->iov);
        kfree(data);
    }
    ...
}

If a user submits an IORING_OP_URING_CMD for encoded reads or writes and it
returns -EAGAIN, the request is queued to io-wq. If the user then cancels the
request or exits the process, io-wq completes the request with -ECANCELED.

Since the command doesn't appear to use io_uring_cmd_mark_cancelable(), btrfs
is not notified when the operation is cancelled. Could this leak the data
struct and its data->iov array upon cancellation?
