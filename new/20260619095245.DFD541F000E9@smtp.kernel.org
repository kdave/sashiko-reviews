Subject: btrfs: tests: add RAID5 RAID-stripe-tree create/update/delete tests

This commit adds RAID5 stripe-tree unit tests, mirroring the existing
coverage for RAID1 profiles. It provides test coverage for simple
create/delete as well as create/update/delete cycles of a full 3-device
stripe. The tests are intended to verify that both data and parity stripes
resolve to the expected devices and physical addresses.

[Severity: Low]
The commit message mentions verifying that each stripe "resolves to the
expected device/physical". The code here correctly verifies that
io_stripe.physical matches phys, but does it also need to check that the
returned io_stripe.dev->devid matches the expected devid?

Since btrfs_get_raid_extent() and btrfs_get_parity_extent() overwrite the
dev pointer in the passed io_stripe struct with the device found in the
tree item, without an explicit assertion on the returned device ID, couldn't
the test pass even if the tree item pointed to an incorrect device?
