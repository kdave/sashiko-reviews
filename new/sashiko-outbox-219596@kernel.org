[Severity: High]
Can waiting on reclaim_bgs_work (and calling btrfs_reclaim_block_groups()
below) in RECLAIM_ZONES deadlock with freeze_super()?

fs/btrfs/block-group.c:btrfs_reclaim_block_groups() {
	if (!btrfs_should_reclaim(fs_info))
		return;

	guard(super_write)(fs_info->sb);
	...
}

When a buffered write or fallocate holds SB_FREEZE_WRITE (or
btrfs_page_mkwrite() holds SB_FREEZE_PAGEFAULT) and blocks in
wait_reserve_ticket(), btrfs_async_reclaim_data_space() runs flush_space()
to satisfy the ticket:

CPU0                CPU1                  kworker
----                ----                  -------
vfs_write()
  file_start_write()
  ...
  reserve_bytes()
    wait_reserve_ticket()
                    freeze_super()
                      sb_wait_write(...,
                        SB_FREEZE_WRITE)
                                          btrfs_async_reclaim_data_space()
                                            flush_space(..., RECLAIM_ZONES)
                                              flush_work(&reclaim_bgs_work)
                                                btrfs_reclaim_block_groups()
                                                  guard(super_write)(sb)

 *** DEADLOCK ***

Once freeze_super() begins waiting on SB_FREEZE_WRITE, guard(super_write)
inside btrfs_reclaim_block_groups() blocks waiting for the filesystem to
thaw, while flush_work(&fs_info->reclaim_bgs_work) even prevents
btrfs_delete_unused_bgs() from freeing unused block groups first.
btrfs_async_reclaim_data_space() then never completes or fails the ticket,
so the writer never drops SB_FREEZE_WRITE and freeze_super() hangs forever.
