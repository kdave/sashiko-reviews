btrfs: fix use-after-free after relocation failure with concurrent COW

This commit fixes a use-after-free issue on the relocation control
structure (fs_info->reloc_ctl) during relocation failures. It introduces
reference counting for the reloc control structure and adds a spinlock
to safely protect reading and writing the pointer.

Link: https://lore.kernel.org/linux-btrfs/6a1df323.bb0696ed.125a22.000a.GAE@google.com/

[Severity: High]
Can this lead to a NULL pointer dereference?

Looking at __del_reloc_root(), get_reloc_control() can return NULL if
relocation is not active or has been unset. 

However, we unconditionally pass rc to put_reloc_control() at the end
of the function. Since put_reloc_control() immediately evaluates
refcount_dec_and_test(&rc->refs) without checking if rc is NULL,
will this trigger a kernel panic when error recovery paths call
__del_reloc_root() after clearing the relocation control structure?
