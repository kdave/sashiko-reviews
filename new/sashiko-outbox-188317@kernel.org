reservations in btrfs_zone_activate(), call_zone_finish(), and
btrfs_check_active_zone_reservation(). It also updates block group zone
loading to unify active zone handling across RAID types and avoids picking
purely conventional data block groups in btrfs_zone_finish_one_bg().

For example, on a degraded mount with a RAID1C3 block group having an empty
sequential stripe 0 (alloc_offset == 0, inactive), a partially written
sequential stripe 1 (active), and a conventional stripe 2 with last_alloc > 0,

then activates bg via btrfs_zone_activate(), after which the check

with -EIO.

and extra reference intact, which can lead to a NULL pointer dereference of
cache->physical_map in btrfs_check_active_zone_reservation() or
do_zone_finish().

[Severity: High]
Does counting WP_MISSING_DEV stripes toward num_sequential misclassify a
degraded conventional block group as a mixed block group?

Just above this hunk in btrfs_load_block_group_zone_info(), every stripe whose
alloc_offset is not WP_CONVENTIONAL increments num_sequential:

	for (i = 0; i < map->num_stripes; i++) {
		ret = btrfs_load_zone_info(fs_info, i, &zone_info[i], active, map, new);
		if (ret)
			goto out;

		if (zone_info[i].alloc_offset == WP_CONVENTIONAL)
			num_conventional++;
		else
			num_sequential++;
	}

When a block group has only conventional stripes on present devices and
WP_MISSING_DEV on a missing device (or offline/readonly zone), num_sequential
is incremented for the missing stripe. This sets
BLOCK_GROUP_FLAG_SEQUENTIAL_ZONE on cache->runtime_flags and enters the
num_conventional > 0 && num_sequential > 0 block above.

Because the WP_MISSING_DEV stripe is not marked active in the active bitmap,
any_active evaluates to false and assign_bit() clears the active bits on the
conventional stripes. Furthermore, because BLOCK_GROUP_FLAG_SEQUENTIAL_ZONE is
set on this block group, if it is activated and placed on
fs_info->zone_active_bgs, btrfs_zone_finish_one_bg() can pick it and finish
it even though finishing its conventional and missing stripes frees no active
zones.
