[Severity: High]
Could this lead to a deadlock between the fsverity read completion worker
and the fserror_worker?

When an fsverity file has corrupted blocks, the read completion verity worker
holds the folio lock and calls fserror_report_data_lost(), which allocates
from a mempool. If the pool is exhausted by concurrent errors, the verity
worker will block waiting for an element while still holding the folio lock.

Meanwhile, fserror_worker processes the queued events and calls iput() on
the inode before freeing the event. If the file has been unlinked and this
is the final reference, iput() triggers synchronous eviction:

fserror_worker()
  -> iput(event->inode)
    -> evict_inode()
      -> truncate_inode_pages_final() (waits on the locked folio)
  -> fserror_free_event() (never reached)
  
Because the fserror_worker blocks in eviction waiting on the folio lock
held by the verity worker, it cannot reach fserror_free_event() to replenish
the mempool. The verity worker is in turn blocked waiting for the mempool,
resulting in a deadlock.
