[Severity: High]
This is a pre-existing issue, but does reloc_root_is_dead() have its read
barrier in the wrong place to properly pair with this smp_wmb()?

In have_reloc_root(), the code checks reloc_root_is_dead(root) before reading
root->reloc_root:

static bool reloc_root_is_dead(const struct btrfs_root *root)
{
	/* ... */
	smp_rmb();
	if (test_bit(BTRFS_ROOT_DEAD_RELOC_TREE, &root->state))
		return true;
	return false;
}

The smp_rmb() is executed before testing the state bit. This fails to enforce
ordering between the state check and the subsequent pointer read in
have_reloc_root(). A CPU might reorder the loads, reading the root->reloc_root
pointer before the state bit, potentially leading to a use-after-free if it
reads a stale non-NULL pointer but sees the state bit as clear.

Should the smp_rmb() be placed after test_bit() and before reading the
pointer?

> +}

This is a pre-existing issue, but could the root reference be leaked if the

Just above this diff hunk, btrfs_get_fs_root() acquires a reference to root:

If this WARN_ON() triggers, it jumps to the out label without calling
btrfs_put_root(root) first. Could this leak the root object and prevent
the filesystem from unmounting cleanly?

[Severity: High]
Can this sequence cause a use-after-free on root?

btrfs_put_root(root) just above drops the reference to root, which could free
the root object if it is the last reference. Calling clear_reloc_root(root)
immediately after that will dereference root. Should clear_reloc_root() be
called before btrfs_put_root()?

[Severity: High]
Are we leaking the reloc_root structure here?

The root->reloc_root pointer holds an explicit reference to the reloc_root
object. While clear_reloc_root(root) sets root->reloc_root = NULL, it does
not call btrfs_put_root(reloc_root) to drop the reference. Although
free_reloc_roots() will later drop the reference associated with the
reloc_roots list, the reference previously held by root->reloc_root appears
to be permanently lost. Should we drop the reference before clearing it?
