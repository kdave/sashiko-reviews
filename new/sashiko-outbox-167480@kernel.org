[Severity: Medium]
In the fstests framework, the _begin_fstest helper initializes the global
status variable to 1 and establishes an EXIT trap. For a test to signal a
successful run, it must explicitly set status=0 before terminating.

Since this script fails to set status=0, won't the EXIT trap execute with
status=1 and cause the framework to unconditionally report a test failure
even on a successful run?

Furthermore, the script ends with _exit 0, which is not a standard Bash
built-in or a standard fstests helper. Executing _exit 0 will likely
produce a command not found error on stderr. Could this mismatch the
golden .out file and guarantee a test failure? 

The standard idiom to conclude a successful fstest is usually:

status=0
exit
