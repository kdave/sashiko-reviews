btrfs: drop the link count of a subvolume inode when deleting the subvolume

This commit drops the VFS link count of a subvolume inode in
btrfs_unlink_subvol() so that a deleted subvolume whose inode is held open
is not listed by btrfs-progs.

[Severity: Critical]
Does this trigger BUG_ON(new_inode->i_nlink == 0) in btrfs_rename() when a
rename overwrites an empty subvolume placeholder directory
(BTRFS_EMPTY_SUBVOL_DIR_OBJECTID)?

new_simple_dir() allocates the placeholder inode with i_nlink == 1, and
btrfs_rename() calls btrfs_unlink_subvol() on new_dentry right before that
BUG_ON():

fs/btrfs/inode.c:btrfs_rename() {
    ...
		if (unlikely(btrfs_ino(BTRFS_I(new_inode)) ==
			     BTRFS_EMPTY_SUBVOL_DIR_OBJECTID)) {
			ret = btrfs_unlink_subvol(trans, BTRFS_I(new_dir), new_dentry);
			if (unlikely(ret)) {
				btrfs_abort_transaction(trans, ret);
				goto out_fail;
			}
			BUG_ON(new_inode->i_nlink == 0);
		}

[Severity: Critical]
When renaming or exchanging a subvolume (BTRFS_FIRST_FREE_OBJECTID),
btrfs_rename() and btrfs_rename_exchange() call btrfs_unlink_subvol()
followed by btrfs_add_link().  Since btrfs_add_link() does not increment
i_nlink, doesn't this leave the live subvolume root inode with i_nlink == 0?

When that inode is later evicted, btrfs_evict_inode() sees i_nlink == 0,
skips its early returns, and runs btrfs_truncate_inode_items() on the live
subvolume root (ino BTRFS_FIRST_FREE_OBJECTID), deleting its root directory
items from the B-tree.  A second rename or deletion before eviction also
hits WARN_ON(inode->i_nlink == 0) in drop_nlink() and underflows i_nlink.

[Severity: Medium]
Does dropping i_nlink to 0 here also cause btrfs_evict_inode() to run
btrfs_truncate_inode_items() and btrfs_orphan_del() when evicting a deleted
subvolume's root inode or an rmdir'd BTRFS_EMPTY_SUBVOL_DIR_OBJECTID stub
inode?

Previously both retained i_nlink == 1 and took the early exits in
btrfs_evict_inode():

fs/btrfs/inode.c:btrfs_evict_inode() {
    ...
	if (inode->i_nlink &&
	    ((btrfs_root_refs(&root->root_item) != 0 &&
	      btrfs_root_id(root) != BTRFS_ROOT_TREE_OBJECTID) ||
	     btrfs_is_free_space_inode(BTRFS_I(inode))))
		goto out;

	if (is_bad_inode(inode))
		goto out;
	/*
	 *Our subvolume was dropped, we haven't cleaned up the full directory
	 * yet so don't do anything here, the cleaner will take care of it
	 * completely.
	 */
	if (inode->i_nlink > 0) {
		BUG_ON(btrfs_root_refs(&root->root_item) != 0 &&
		       btrfs_root_id(root) != BTRFS_ROOT_TREE_OBJECTID);
		goto out;
	}
    ...
}

With i_nlink == 0, evicting a deleted subvolume's root inode synchronously
joins transactions to COW tree blocks and truncate objectid 256 instead of
leaving tree deletion to the cleaner thread, and evicting an rmdir'd stub
inode runs B-tree truncation and orphan deletion for objectid 2 on the
parent subvolume root.
