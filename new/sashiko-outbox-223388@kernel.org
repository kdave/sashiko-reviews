[Severity: High]
This problem wasn't introduced by this patch, but can run_delalloc_cow()
double unlock locked_folio [1] on a zoned filesystem when
cow_file_range() fails on a subsequent loop iteration?

fs/btrfs/inode.c:run_delalloc_cow() {
    ...
	while (start <= end) {
		ret = cow_file_range(inode, locked_folio, start, end,
				     &done_offset, COW_FILE_RANGE_KEEP_LOCKED);
		if (ret)
			return ret;
		extent_write_locked_range(&inode->vfs_inode, locked_folio,
					  start, done_offset, wbc);
		start = done_offset + 1;
	}
    ...
}

When active zones are exhausted mid-range, cow_file_range() sets
done_offset to the end of the allocated prefix and returns 0.
extent_write_locked_range() then submits and unlocks the folios in
[start, done_offset] via btrfs_folio_end_lock(), including locked_folio.

If the next iteration of cow_file_range() fails, run_delalloc_cow()
returns the error to extent_writepage() or submit_uncompressed_range(),
which assume locked_folio is still locked on error and unlock it a second
time.  This triggers a bug check in folio_unlock() or underflows
bfs->nr_locked on subpage and large folios, permanently wedging the folio
lock.
