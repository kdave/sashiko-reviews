[Severity: High]
Can this error path bypass the out_unlock label and leave the lock held?

If tree_mod_dont_log() returns false (which implicitly acquires
fs_info->tree_mod_log_lock) and tree_mod_log_free_eb() returns an error,
jumping directly to free_tms bypasses the out_unlock label.

This skips the write_unlock(&fs_info->tree_mod_log_lock) call, which could
subsequently deadlock the filesystem on the next lock acquisition.

Should this jump instead target out_unlock so the write lock is released?
