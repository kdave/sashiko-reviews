[Severity: High]
Can this race with bdev_thaw() and corrupt the counter?

Looking at bdev_thaw(), the bd_fsfreeze_count is dropped to 0 prematurely
before the actual thaw operation occurs:

bdev_thaw()
    nr_freeze = atomic_dec_if_positive(&bdev->bd_fsfreeze_count);
    ...
    error = bdev->bd_holder_ops->thaw(bdev);

If bdev_deny_freeze() is called concurrently during this window, it locklessly
checks atomic_dec_unless_positive(). Since it sees 0, it decrements the
counter to -1 and incorrectly succeeds, assuming no freeze is active. This
allows the caller to mutate the device while it is technically still frozen.

Furthermore, if the thaw() operation fails, bdev_thaw() blindly attempts to
roll back:

bdev_thaw()
    ...
    if (error)
        atomic_inc(&bdev->bd_fsfreeze_count);

Because the denier changed the counter to -1, this rollback increments it to
0 instead of 1, corrupting the sign-encoded counter.
