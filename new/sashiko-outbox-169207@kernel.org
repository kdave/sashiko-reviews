[Severity: High]
Does dropping the lock without holding a local reference to tgt expose it
to a concurrent use-after-free?

If two threads concurrently process extent buffers for a new metadata block
group, could they both evaluate *active_bg != block_group, read the same
tgt pointer, and drop the lock?

If Thread 1 finishes its writebacks first, reacquires the lock, observes
*active_bg == tgt, clears *active_bg, and calls btrfs_put_block_group(),
the block group could be freed if it has no other references (e.g. if
concurrently removed from the cache tree via btrfs_delete_unused_bgs()).

When Thread 2 resumes, wouldn't it blindly dereference the freed tgt inside
wait_eb_writebacks() and do_zone_finish()? Should the code take a local
reference via btrfs_get_block_group() before dropping the lock?
