[Severity: Medium]
Should btrfs_zoned_dev_avail_bytes() also exclude the non-overlapping zones
containing the regular superblock offsets returned by btrfs_sb_offset()?

During chunk allocation, btrfs_find_allocatable_zones() in fs/btrfs/zoned.c
skips both the log-structured superblock zones at sb_zone_number() and the
zones containing the regular superblock positions at btrfs_sb_offset():

fs/btrfs/zoned.c:btrfs_find_allocatable_zones() {
	...
			/* We also need to exclude regular superblock positions */
			sb_pos = btrfs_sb_offset(i);
			if (!(pos + num_bytes <= sb_pos ||
			      sb_pos + BTRFS_SUPER_INFO_SIZE <= pos)) {
				have_sb = true;
				pos = ALIGN(sb_pos + BTRFS_SUPER_INFO_SIZE,
					    zinfo->zone_size);
				break;
			}
	...
}

Similarly, btrfs_exclude_super_stripes() in fs/btrfs/block-group.c rejects
any block group on a zoned filesystem that maps a btrfs_sb_offset() range.

While btrfs_sb_offset(0) at 64 KiB always falls inside zone 0 (overlapping
mirror 0's log zones), the other two regular superblock mirrors do not
always overlap with the log zones at sb_zone_number() (0B, 512 GiB, and
4 TiB):

- For mirror 1, btrfs_sb_offset(1) is at 64 MiB. When zinfo->zone_size is
  smaller than 64 MiB (4 MiB, 8 MiB, 16 MiB, or 32 MiB), mirror 0's two log
  zones end at or before 64 MiB, so the zone containing 64 MiB does not
  overlap any sb_zone_number() log zone.

- For mirror 2, btrfs_sb_offset(2) is at 256 GiB. For every supported
  zone_size (4 MiB up to 8 GiB), the zone containing 256 GiB never overlaps
  any sb_zone_number() log zone.

Because btrfs_zoned_dev_avail_bytes() only subtracts the log zones at
sb_zone_number(), won't btrfs_statfs() -> btrfs_calc_avail_data_space() ->
btrfs_zoned_dev_avail_bytes() over-report available space by 1 to 2 zones
per device on devices larger than 64 MiB (when zone_size < 64 MiB) or larger
than 256 GiB?

In addition, with follow-up commit 39007970abec ("btrfs: zoned: keep a zone
free for relocation when allocating data chunks"), could this over-counting
allow btrfs_zoned_data_chunk_allowed() to allocate the last free zone that
was meant to be reserved for relocation?
