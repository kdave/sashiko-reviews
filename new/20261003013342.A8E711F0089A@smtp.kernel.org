[Severity: High]
Does this allocation sleep while holding the fs_info->qgroup_lock?

The spin_lock() call earlier in qgroup_auto_inherit() initiates an atomic
context. However, kzalloc() is called here with GFP_NOFS, which includes
__GFP_DIRECT_RECLAIM and allows the allocator to sleep while waiting for
memory reclaim.

Since this code path is reachable via standard filesystem operations when
creating a subvolume with simple quotas enabled, could this regression
trigger a 'BUG: scheduling while atomic' panic if the allocator blocks?
