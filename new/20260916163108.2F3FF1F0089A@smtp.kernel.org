btrfs: remove reduntant eb generation check in btrfs_buffer_uptodate()

This commit removes a check in btrfs_buffer_uptodate() comparing the extent
buffer's generation to parent_transid, under the assumption that it is
redundant.

[Severity: Critical]
Does removing this block cause the function to return 1 (success) when the
generation actually mismatches?

If parent_transid is non-zero and the generation does not match, the previous
if statement in this function is bypassed:

	if (!parent_transid || btrfs_header_generation(eb) == parent_transid) {
		...
		return 1;
	}

Without the removed error handling block, execution unconditionally falls
through to the final return statement at the end of the function, which returns
1.

Will this cause the filesystem to silently trust and parse invalid or outdated
metadata blocks as valid, bypassing COW guarantees and potentially leading to
on-disk data corruption or out-of-bounds memory accesses?
