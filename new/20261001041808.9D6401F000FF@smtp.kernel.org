[Severity: Medium]
Does this test silently fail to degrade the array?

The variable SCRATCH_DEV_NAME is not standard for pools in fstests
(typically SCRATCH_DEV_POOL is used), so dev2 evaluates to an empty string.

Consequently, wiping the empty device path silently fails due to the
redirected output in workload(), leaving the array fully healthy and
preventing the intended testing of the degraded RMW path.
