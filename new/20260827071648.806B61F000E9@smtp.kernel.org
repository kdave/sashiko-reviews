btrfs: reject new qgroup rescan during subvolume dropping

This commit introduces BTRFS_QGROUP_RUNTIME_BIT_REJECT_RESCAN to prevent
new qgroup rescans during a subvolume drop. It also updates quota enable
and disable functions to handle the new flag without overriding it.

[Severity: High]
Since cleaner_kthread() sets BTRFS_QGROUP_RUNTIME_BIT_REJECT_RESCAN here
without acquiring subvol_sem or qgroup_ioctl_lock, can this race with a
concurrent quota enable?

If a user executes btrfs quota enable concurrently, qgroup_rescan_init()
encounters the REJECT_RESCAN bit and overloads the return code
-EINPROGRESS. Looking at btrfs_quota_enable(), it catches this specific
error code and assumes another thread has already queued the rescan:

fs/btrfs/qgroup.c:btrfs_quota_enable() {
    ...
    ret = qgroup_rescan_init(fs_info, 0, 1);
    if (!ret) {
        qgroup_rescan_queued = true;
        btrfs_queue_work(fs_info->qgroup_rescan_workers,
                 &fs_info->qgroup_rescan_work);
    } else {
        ASSERT(ret == -EINPROGRESS);
        ret = 0;
    }
    ...
}

Does this mean btrfs_quota_enable() will fail to initialize accounting
without returning an error, and leave quotas inconsistent because the
rescan is never executed?

[Severity: High]
Does skipping the clearance of BTRFS_QGROUP_STATUS_BIT_RESCAN here cause
the bit to leak and prevent future rescans?

This modifies btrfs_quota_disable() to leave the RESCAN bit for the rescan
worker to handle. However, during quota disable, btrfs_qgroup_rescan_worker()
evaluates stopped as true and CANCEL_RESCAN as false, which bypasses the bit
clearance:

fs/btrfs/qgroup.c:btrfs_qgroup_rescan_worker() {
    ...

                 &fs_info->qgroup_flags))
        clear_bit(BTRFS_QGROUP_STATUS_BIT_RESCAN, &fs_info->qgroup_flags);
    ...
}

Because btrfs_quota_enable() is changed to use set_bit() instead of overwriting
the flags, the leaked RESCAN bit is carried forward. Will any future
qgroup_rescan_init() invocation hit this stale bit and abort with
-EINPROGRESS, preventing future qgroup rescans?
