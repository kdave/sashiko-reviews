[Severity: High]
Does adding USEBACKUPROOT here without also setting CLEAR_CACHE introduce a
space cache corruption issue?

If a user mounts a corrupted filesystem with "-o rescue=all", the mount
succeeds using a backup root. Because CLEAR_CACHE is not explicitly set by
rescue=all, the block group space caches on disk are not invalidated in memory.

When the initial mount completes, USEBACKUPROOT is cleared from the
persistent mount options. If the user subsequently remounts read-write, the
read-only restriction on USEBACKUPROOT no longer applies.

Could the filesystem then begin allocating space using the obsolete
free-space cache, leading to data corruption by overwriting extents that
are actually in use by the backup root?
